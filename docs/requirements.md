### 1.1 文書の目的

本書は、訪問介護に従事する一従業員が、自身の給与見込み額を月ごとに把握するためのシステムについて、要求事項、前提条件、制約、決定事項および受入条件を整理することを目的とする。

本書における給与額は、利用者が入力した勤務内容と設定値に基づく計算結果であり、勤務先が発行する給与明細または法令上の正式な賃金計算を代替するものではない。

### 1.2 本書の位置づけ

- 本書は初期リリースの確定要件を整理したものであり、要件を変更した場合は変更履歴と関連文書を更新する。
- 詳細な画面設計、データベース設計、計算式およびテスト仕様は、要件確定後に別途定義する。
- 訪問介護や賃金に関する一般的な業務知識は、厚生労働省その他の国の公的資料を参考にする。ただし、本システム固有の計算ルールは原則として利用者の指定を優先する。
- 公的資料を参照して要件または仕様を決定した場合は、資料名、発行元、版または参照日を記録する。

## 2. システムの目的

### 2.1 目的

日々の訪問実績を最小限の操作で記録し、設定された単価、割増および訪問件数加算に基づいて、対象給与期間の給与見込み額と日別の内訳を確認できるようにする。

### 2.2 対象利用者

- 訪問介護に従事する一従業員本人
- 1台のAndroid端末で1人が利用することを基本とする。
- 複数従業員、管理者および事業所単位の管理は対象としない。

### 2.3 成功条件

- 利用者が日々の記録を少ない入力項目と操作回数で登録できる。
- 利用者が曜日ごとの基本シフトをあらかじめ登録し、該当日の勤務実績として利用できる。
- 利用者が任意の給与期間について、給与見込み額とその根拠となる内訳を確認できる。
- 利用者が勤務先の給与体系に合わせて、サービス種類、単価、割増、件数加算、月額手当および締め日を設定できる。
- 端末変更時に、データをエクスポートして別端末へ移行できる。
- インターネット接続を必要とせず、端末内で全機能を利用できる。

## 3. スコープ

### 3.1 対象範囲

- サービス種類および時間区分の設定
- 基本単価の設定
- 休日、夜間などの割増設定
- 訪問件数に応じた加算設定
- 給与期間ごとの任意の月額手当設定
- 給与締め日の設定
- 日々の勤務内容の登録、編集、複製および削除
- 曜日ごとの基本シフトの登録、および基本シフトから勤務実績への反映
- カレンダーによる日別記録と日別給与見込み額の確認
- 給与期間ごとの給与見込み額および内訳の確認
- 設定および勤務データの端末内保存
- データのエクスポートおよびインポート
- Android向けインストールファイルの生成と個別配布

### 3.2 対象外

- 複数従業員の管理および集計
- 事業所向けの勤怠管理、複数従業員のシフト作成・調整、請求管理および給与支払い
- 雇用主が発行する正式な給与明細の作成
- 社会保険料、税金、控除、交通費などの計算。ただし、将来要件として追加される可能性はある。
- クラウド同期、サーバー保存およびWebサービスとの連携
- ユーザーアカウント、ログインおよび権限管理
- 利用者氏名、訪問先氏名、住所など、給与計算に不要な個人情報の管理
- Google Playでの公開および配布
- 複数端末間のリアルタイム同期
- 実績管理そのものを目的とした詳細な記録、承認または監査機能

### 3.3 システム境界

- 本システムは、Android端末上で完結する単一のアプリケーションとする。
- 本書における「バックエンド」は、端末内で動作するC#のドメイン層およびアプリケーション層を指し、外部サーバーや常駐サービスを意味しない。
- 画面、給与計算、端末内保存およびファイル入出力をAPKへ同梱する。
- システム境界の外へデータが移動するのは、利用者がエクスポートまたはファイル共有を明示的に実行した場合に限る。
- Androidのファイル選択機能で利用者が外部ストレージサービスを選んだ場合の転送は、そのサービスと利用者の管理範囲とし、本アプリ自身は外部の通信先へ接続しない。

## 4. 用語

| 用語 | 定義 |
| --- | --- |
| サービス種類 | 「身体」「生活」「移動」など、給与単価を区別するための分類 |
| 時間区分 | サービス種類に対応する所要時間または単位。「身体1＝30分」など |
| 勤務記録 | 1回の訪問または給与計算対象となる1件の入力データ |
| 基本シフト | 曜日ごとの標準的な勤務内容をあらかじめ登録し、勤務実績の作成に再利用するためのテンプレート。基本シフト自体は給与計算の対象としない |
| シフト反映 | 基本シフトの内容を指定日の勤務記録として登録する操作 |
| 基本単価 | サービス種類および時間区分に対して設定される、割増前の給与額または時給 |
| 割増 | 休日、夜間などの条件を満たした場合に基本給与へ追加される金額または割合 |
| 件数加算 | 訪問件数に応じて、1件単位などで給与へ追加される金額 |
| 月額手当 | 利用者が指定した給与期間の合計へ1回加算する任意の固定額。勤務記録または日へは配賦しない |
| 給与期間 | 設定された締め日に基づき、月次の給与見込み額を計算する期間 |
| 給与見込み額 | 本システムの設定と勤務記録から算出した参考金額 |

## 5. 業務要件

### BR-01 個人利用

本システムは、一従業員が自身の給与見込み額を確認するために使用する。従業員情報を複数登録する機能は持たない。

### BR-02 給与計算への特化

本システムは給与見込み額の把握を目的とし、実績管理に必要な情報を網羅することは目的としない。給与計算に使用しない入力項目は、原則として設けない。

### BR-03 設定可能な給与体系

勤務先ごとに異なる給与体系へ対応するため、少なくとも以下を利用者が設定できること。

- サービス種類
- サービス種類に属する時間区分
- 基本単価
- 休日、夜間などの割増条件と加算内容
- 訪問件数に応じた加算内容
- 給与期間ごとの任意の月額手当
- 給与締め日

### BR-04 月次計算

給与見込み額は、利用者が設定した締め日に基づく給与期間ごとに計算する。

### BR-05 オフライン完結

入力、設定、計算、閲覧、エクスポートおよびインポートは、外部サービスとの通信なしで完結すること。

### BR-06 基本シフトによる入力省力化

繰り返し発生する勤務について、曜日ごとの基本シフトから勤務記録を作成できるようにし、日々の入力負担を軽減する。基本シフトは実績の初期値として扱い、実際の勤務内容と異なる場合は反映後の勤務記録を修正できること。

## 6. 機能要件

### 6.1 初期設定

#### FR-INIT-01 初回利用

初回起動時に、給与計算を開始するために必要な設定へ利用者を案内すること。

#### FR-INIT-02 初期値

サービス種類、時間区分および標準時間の初期値は、[初期設定定義](default_setting.md)に従って提供すること。利用者は初期値を編集、追加および無効化できること。

#### FR-INIT-03 初期設定の最小化

初回利用時に必須とする設定は、正しい給与計算に必要な最小限の項目に限定すること。

### 6.2 サービス種類・時間区分設定

#### FR-CONF-01 サービス種類

「身体」「生活」「移動」などのサービス種類を管理できること。

サービス種類について、少なくとも以下の情報を保持する。

- 表示名
- 表示順
- 使用中または無効の状態

#### FR-CONF-02 時間区分

各サービス種類に対し、「身体1＝30分」などの時間区分を管理できること。

時間区分について、少なくとも以下の情報を保持する。

- 表示名
- 所要時間または給与計算上の単位
- 表示順
- 使用中または無効の状態

#### FR-CONF-03 設定削除時の保護

基本シフトまたは勤務記録から参照されているサービス種類・時間区分は、テンプレートの内容や過去の計算根拠を失わない方法で無効化または削除できること。

### 6.3 基本単価設定

#### FR-RATE-01 単価設定

サービス種類および時間区分ごとに基本単価を設定できること。

#### FR-RATE-02 単価方式

給与計算で使用する単価方式は、サービス種類および時間区分ごとに次のいずれかを選択できること。初期値は時間に比例して計算する時給方式とする。

- 時間に比例して計算する時給方式
- 時間区分ごとの固定額方式

#### FR-RATE-03 金額入力

金額は整数の日本円として入力、保存および表示すること。計算過程で端数が生じた場合はその時点で1円未満を切り上げ、小数値を後続の計算へ持ち越さないこと。

### 6.4 割増設定

#### FR-PREM-01 割増種別

休日、夜間など、給与へ加算する条件を複数設定できること。「休日」「夜間」の名称に固定せず、利用者の給与体系に合わせて表示名を設定できること。

#### FR-PREM-02 割増条件

割増には、必要に応じて以下を設定できること。

- 表示名
- 適用する曜日または休日区分
- 適用する個別の日付
- 適用する開始時刻と終了時刻
- 加算方法
- 加算値
- 適用対象となるサービス種類または全種類
- 使用中または無効の状態

#### FR-PREM-03 加算方法

割増の加算方法として、次の3方式から選択できること。休日および夜間の初期値は、時間当たりの固定額加算とする。

- 基本給与に対する割合加算
- 時間当たりの固定額加算
- 勤務記録1件当たりの固定額加算

#### FR-PREM-04 時間帯をまたぐ勤務

勤務時間の一部のみが夜間などの割増条件に該当する場合、該当部分だけに割増を適用すること。この計算に時刻が必要な場合に限り、勤務記録の開始時刻および終了時刻を必須入力とすること。

#### FR-PREM-05 複数割増

1件の勤務記録が複数の割増条件に該当する場合は、該当する割増をすべて重複適用し、それぞれの割増額を加算すること。

#### FR-PREM-06 休日判定

休日割増の初期値は土曜日、日曜日および国民の祝日とする。利用者は、休日として扱う曜日と、国民の祝日を休日に含めるかを変更できること。事業所独自の休日は、利用者が端末内で個別の日付を指定できること。

国民の祝日はアプリへ同梱したデータを用いて外部通信なしで判定し、祝日データの更新が必要な場合はアプリ更新に含めること。

### 6.5 件数加算設定

#### FR-COUNT-01 件数加算

訪問件数に応じた加算を設定できること。

#### FR-COUNT-02 加算単位

勤務記録1件を訪問1件とし、勤務記録1件につき固定額を加算すること。複数の訪問を1件の勤務記録へまとめて登録する機能は設けないこと。

#### FR-COUNT-03 適用条件

件数加算について、必要に応じて以下を設定できること。

- 表示名
- 1件当たりの加算額
- 適用対象となるサービス種類または全種類
- 適用期間または適用開始日
- 使用中または無効の状態

### 6.6 給与期間設定

#### FR-PERIOD-01 締め日

利用者が給与締め日を設定できること。

#### FR-PERIOD-02 月末締め

締め日として月末を選択できること。

#### FR-PERIOD-03 給与期間の表示

選択中の給与期間について、「給与算定開始日」および「給与算定終了日」を明示すること。給与期間が年をまたぐ場合は、開始日と終了日の両方に年および月を表示すること。

#### FR-PERIOD-04 給与期間の境界

ある締め日の翌日から次の締め日までを1つの給与期間とする。勤務記録をどの給与期間へ含めるかは勤務日を基準とする。日付をまたぐ勤務は開始日を勤務日として扱うこと。

#### FR-PERIOD-05 存在しない日付

締め日が29日、30日または31日であり、対象月にその日が存在しない場合は、その月の末日を締め日とすること。

#### FR-PERIOD-06 締め日の変更

締め日の変更は、利用者が変更対象として指定した月以降の給与期間へ適用し、それより前の給与期間には反映しないこと。

### 6.7 基本シフト

#### FR-SHIFT-01 曜日ごとの基本シフト登録

月曜日から日曜日までの曜日ごとに、基本シフトを登録、編集、並べ替え、無効化および削除できること。

#### FR-SHIFT-02 基本シフトの勤務内容

基本シフトには、給与計算と実績登録に必要な範囲で、少なくとも以下を設定できること。

- 曜日
- サービス種類
- 時間区分または勤務時間
- 必要な場合の開始時刻および終了時刻
- 同一曜日内の表示順
- 使用中または無効の状態

同じ曜日に複数の基本シフトを登録できること。

#### FR-SHIFT-03 基本シフトの反映

カレンダーで日付を選択した際に、その曜日の基本シフトを当日の勤務入力へ自動的に反映すること。反映単位は選択した1日とし、複数日または給与期間全体への一括反映は初期リリースに含めないこと。

曜日ごとに複数種類の基本シフトを登録でき、選択日の入力へ反映する基本シフトを確認できること。

#### FR-SHIFT-04 反映内容の確認

基本シフトから自動入力された内容について、対象日、登録予定の勤務記録および既存の勤務記録の有無を確認できること。利用者が登録を確定するまで勤務実績として保存せず、給与計算へ含めないこと。反映できない設定が含まれる場合は、対象と理由を表示すること。

#### FR-SHIFT-05 実績としての独立

基本シフトから作成した勤務記録は、通常の勤務記録として編集および削除できること。反映後に基本シフトを変更または削除しても、作成済みの勤務記録を自動変更または削除しないこと。

#### FR-SHIFT-06 給与計算への反映

基本シフト自体および未登録の自動入力内容は給与見込み額へ含めず、利用者が勤務記録として登録を確定した時点で給与計算の対象とすること。

#### FR-SHIFT-07 二重登録の防止

同じ基本シフトを同じ日へ複数回反映しようとした場合や、対象日に既存の勤務記録がある場合、意図しない二重登録を防止すること。既存記録と異なる勤務を追加する必要があるため、一律に禁止せず、重複の可能性と反映結果を利用者が判断できること。

#### FR-SHIFT-08 設定不備

基本シフトが参照するサービス種類、時間区分または計算設定が無効もしくは不足している場合、勤務記録として黙って反映せず、修正が必要な基本シフトと理由を表示すること。

### 6.8 日々の勤務入力

#### FR-WORK-01 勤務記録の登録

カレンダー上の日付を選択し、その日に発生した勤務記録を登録できること。

#### FR-WORK-02 必須入力

勤務記録の必須入力は、給与計算に必要な最小限の項目とする。候補は次のとおりとし、適用する計算ルールに応じて不要な項目を省略する。

- 日付
- サービス種類
- 時間区分または勤務時間
- 開始時刻および終了時刻

基本単価、割増額、件数加算額および締め日は設定から自動適用し、日々の勤務記録へ重複して入力させないこと。

#### FR-WORK-03 入力の省力化

日々の入力を省力化するため、初期リリースでは少なくとも以下を提供すること。

- 初期値の自動選択
- 直前に使用した値の再利用
- 曜日ごとの基本シフトからの反映
- よく使う勤務内容のお気に入りまたは定型登録
- 過去の日の勤務記録を日単位で複製する機能

日単位で複製する場合も、複数の訪問を1件の勤務記録へまとめず、元の日の各勤務記録を個別の勤務記録として作成すること。

#### FR-WORK-04 編集・削除

登録済みの勤務記録を編集および削除できること。削除前には確認メッセージを表示すること。

#### FR-WORK-05 入力検証

計算不能または矛盾する入力を保存しないこと。例として、未設定の単価、入力可能範囲外の時刻または負の金額を検出し、修正方法が分かるメッセージを表示すること。

#### FR-WORK-06 日付をまたぐ勤務

深夜帯など日付をまたぐ勤務は1件の勤務記録として扱うこと。終了時刻が開始時刻以前の場合は翌日の時刻として扱い、勤務日および給与期間は開始日を基準とすること。
→開始の日時をその日の勤務とみなす。また、日付をまたいでも1件として扱う。

### 6.9 カレンダー・日別表示

#### FR-CAL-01 月間カレンダー

月間カレンダーを表示し、日付を選択できること。

#### FR-CAL-02 日別の状態表示

カレンダー上で、勤務記録が存在する日を識別できること。

#### FR-CAL-03 日別給与

選択した日について、勤務記録の一覧、各記録の給与見込み額および日合計を確認できること。

基本シフトが登録されている曜日では、選択した日の基本シフトを勤務記録へ反映する操作を開始できること。

#### FR-CAL-04 月の移動

前月、翌月および当月へ移動できること。

### 6.10 給与計算・集計

#### FR-CALC-01 給与見込み額の計算

勤務記録と、その勤務に適用される基本単価、割増および件数加算を使用して給与見込み額を計算すること。

#### FR-CALC-02 計算内訳

給与見込み額について、少なくとも以下の内訳を確認できること。

- 基本給与
- 割増額（割増種別ごと）
- 件数加算額
- 月額手当（設定されている場合）
- 合計額

#### FR-CALC-03 期間集計

給与期間ごとに、日別給与見込み額、月額手当および期間合計を表示すること。

#### FR-CALC-04 再計算

勤務記録または適用対象の設定を変更した場合、影響する給与見込み額を再計算すること。

#### FR-CALC-05 計算の再現性

同じ勤務記録と設定に対して、常に同じ計算結果を返すこと。

#### FR-CALC-06 計算根拠

利用者が計算結果を確認できるよう、適用された単価、割増および件数加算を勤務記録単位で表示できること。

#### FR-CALC-07 設定変更と過去データ

単価および割増設定の変更は、利用者が変更対象として指定した年月に属する勤務記録だけへ反映し、他の年月の勤務記録へは反映しないこと。過去の給与見込み額を再現できるよう、年月ごとに適用した設定を保持すること。

#### FR-CALC-08 設定不備の表示

勤務記録に適用可能な単価または計算設定が存在せず正しく計算できない場合、推測値を表示せず、未計算であることと不足している設定を明示すること。

#### FR-CALC-09 月額手当

初期リリースでは、基本給与、割増および件数加算に加え、給与期間ごとの月額手当を任意で設定できること。月額手当について、表示名、金額および対象給与期間を指定できること。

月額手当は勤務記録単位または日単位へ配賦せず、対象の給与期間合計へ1回加算すること。設定されていない場合は0円として扱うこと。

### 6.11 データのエクスポート・インポート

#### FR-DATA-01 エクスポート

端末内に保存されている設定、基本シフトおよび勤務記録を、移行可能な単一ファイルとしてエクスポートできること。

エクスポートファイルには、別端末で給与見込み額と基本シフトを再現するために必要な年月ごとの設定、月額手当、基本シフトおよび勤務記録を含めること。一時データや再生成可能なキャッシュは含めないこと。

エクスポートファイルは暗号化またはパスワード保護を行わない。保存先に応じて第三者が閲覧できる可能性があることを、エクスポート実行前に利用者へ案内すること。

#### FR-DATA-02 インポート

本システムがエクスポートしたファイルを選択し、設定、基本シフトおよび勤務記録をインポートできること。

#### FR-DATA-03 形式の識別

エクスポートデータに形式バージョンを含め、将来のアプリ更新後も互換性を判定できること。

#### FR-DATA-04 事前検証

インポート前に、ファイル形式、バージョンおよび必須データを検証すること。不正または非対応のファイルでは既存データを変更せず、理由をメッセージで表示すること。

#### FR-DATA-05 取り込み方式

インポートは既存の設定、月額手当、基本シフトおよび勤務記録をすべて置き換える方式とする。置換前に対象範囲と既存データが失われることを説明し、利用者の確認を得ること。利用者が取り消した場合またはインポートに失敗した場合は、既存データを変更しないこと。

#### FR-DATA-06 ファイル授受

Android標準のファイル選択・共有機能を利用し、利用者が保存先および読み込み元を選択できること。

### 6.12 メッセージ

#### FR-MSG-01 操作結果

保存、削除、インポート、エクスポートなど、結果の確認が必要な操作について、成功または失敗を利用者へメッセージで通知すること。

#### FR-MSG-02 エラー案内

エラーメッセージは技術的な内部情報ではなく、発生内容と利用者が取れる対応を日本語で示すこと。

#### FR-MSG-03 破壊的操作の確認

削除、全データの置換、初期化など、元に戻せない可能性がある操作では事前に確認メッセージを表示すること。

## 7. 給与計算ルールの基本モデル

本節は確定した業務ルールに基づく基本モデルを示す。演算順序と具体例は、別途作成する給与計算仕様書でこのモデルと矛盾しないように定義する。

### 7.1 勤務記録単位の計算

```text
勤務記録の給与見込み額
  = 基本給与
  + 適用される割増額の合計
  + 適用される件数加算額の合計
```

### 7.2 日単位の計算

```text
日別給与見込み額
  = 当日の勤務記録の給与見込み額の合計
```

### 7.3 給与期間単位の計算

```text
給与期間の給与見込み額
  = 対象期間に含まれる日別給与見込み額の合計
  + 対象給与期間に設定された月額手当
```

### 7.4 確定した計算原則

- 基本単価は、時給方式と時間区分ごとの固定額方式から選択できる。初期値は時給方式とする。
- 割増は、割合、時間当たり固定額または勤務記録1件当たり固定額から選択できる。
- 複数の割増条件を満たす場合は、各割増を重複適用して加算する。
- 時刻を必要とする割増は、該当する時間部分だけを計算対象とする。
- 休日の初期値は土曜日、日曜日および国民の祝日とし、利用者が変更できる。
- 勤務記録1件を訪問1件として扱う。
- 金額は整数円とし、計算途中で生じた1円未満の端数はその時点で切り上げる。
- 設定変更は指定した年月だけへ反映し、他の年月の計算結果を変更しない。
- 月額手当は対象給与期間へ1回加算し、勤務記録または日へ配賦しない。

## 9. データ要件

### 9.1 保存対象

少なくとも以下を端末内へ保存する。

- アプリ設定
- 給与締め日
- サービス種類
- 時間区分
- 基本単価とその適用期間
- 割増設定とその適用期間
- 件数加算設定とその適用期間
- 月額手当とその対象給与期間
- 曜日ごとの基本シフト
- 勤務記録
- 基本シフトを反映して作成した勤務記録を識別するための情報
- データ形式のバージョン

給与計算に不要な利用者氏名、訪問先氏名、住所その他の個人情報は保存しない。

### 9.2 保存方式

- データはAndroid端末内に保存する。
- 保存容量を必要以上に消費しない、コンパクトな構造とする。
- 日別合計や給与期間合計など、元データから再計算できる値は原則として重複保存しない。性能上キャッシュする場合は、元データから再構築できること。
- 構造化データの保存には、端末内データベースを利用する。
- 画像、音声その他の大容量データは要件に含めない。
- データの整合性を保ち、アプリの強制終了後も確定済みの入力を失わないこと。

### 9.3 データ保持

- 利用者が削除または初期化しない限り、勤務記録を端末内に保持する。
- 保持年数の上限は現時点では設けない。
- アプリのアンインストール時には端末内データが失われる可能性があるため、エクスポートによるバックアップを案内すること。

### 9.4 データ精度

- 金額計算には浮動小数点数による誤差が生じない数値表現を用いること。
- 勤務日は端末のローカル日付として保持し、端末のタイムゾーンを変更しても意図せず別の日へ移動しないこと。
- 時刻は勤務日のローカル時刻として扱う。
- タイムゾーン変更時の扱いは、詳細設計で定義する。

## 10. 非機能要件

### 10.1 対応環境

- Android向けアプリケーションとして動作すること。
- Android 10（APIレベル29）以上を対応対象とすること。
- 画面はスマートフォンでの縦向き利用を優先する。初期リリースでは横向きおよびタブレット専用の画面最適化を必須としない。
- 配布対象のCPUアーキテクチャは利用予定端末で動作するものを選び、リリース前に代表端末で確認すること。

### 10.2 配布・更新

- Google Playでは配布せず、署名済みAPKを個別に配布し、サイドローディングでインストールする。
- Android App Bundle（AAB）ではなく、端末へ直接インストールできるAPKを配布物の基本とする。
- APKには正式な署名を行い、更新時も同一の署名鍵を使用する。
- 署名鍵は紛失または漏えいしない方法で管理する。
- バージョン番号と表示用バージョン名を管理し、インストール済みアプリを更新できること。
- 更新インストールによって既存データが失われないこと。
- 配布元とファイルの真正性を利用者が確認できる方法は、運用設計で定める。

### 10.3 アーキテクチャ

- オニオンアーキテクチャを採用する。
- 給与計算のドメインルールをUI、Android固有機能およびデータ保存方式から分離する。
- 依存関係は外側の層から内側の層へ向け、ドメイン層はUIやデータベースの実装へ依存しないこと。
- 想定する論理層は次のとおりとする。
  - Domain：給与計算ルール、値オブジェクト、ドメインモデル
  - Application：ユースケース、入力検証、インターフェース
  - Infrastructure：端末内データベース、ファイル入出力、Android固有処理
  - Presentation：画面、状態管理、ユーザー操作

### 10.4 技術構成

- 給与計算を含むバックエンド／業務ロジックはC#で実装する。
- UIは.NET MAUIのXAMLおよびC#で実装する。初期リリースではTypeScript、Angular、Blazor HybridおよびHybridWebViewを採用しない。
- Domain層およびApplication層はUIフレームワークに依存しない通常の.NETクラスライブラリとし、Presentation層からApplication層をプロジェクト参照して同一プロセス内で呼び出す。
- Android固有のファイル保存等はApplication層で定義したインターフェースを介し、Infrastructure層の.NET MAUI／Android実装へ分離する。
- 採用する.NETおよび.NET MAUIのメジャーバージョンは、実装開始時点の安定版とする。サポート期間を確認し、サポート終了前に後継安定版へ更新する。
- 実装開始時の小規模な実行検証で少なくとも次を確認する。
  - Android端末上でC#の業務ロジックとUIを安全に接続できること
  - 端末内データベースを利用できること
  - ファイルのエクスポートとインポートができること
  - 署名済みAPKを生成し、更新インストールできること
- 技術選定の比較、成立性調査、未実施の実行検証および判断理由は、[ADR-0001 UIフレームワークの選定](adr/0001-ui-framework.md)に記録する。

### 10.5 性能

- 30年分、1日当たり最大20件、合計最大22万件の勤務記録を性能試験の基準データ量とする。
- 代表端末上で、勤務記録の保存後に日別および給与期間の計算結果を2秒以内に表示すること。
- 代表端末上で、カレンダー表示、給与期間の切り替えおよび期間集計結果を、操作開始から2秒以内に表示すること。

### 10.6 信頼性・データ保護

- 保存処理の途中で失敗した場合に、データが部分的な不整合状態にならないこと。
- インポート処理に失敗した場合に、既存データを維持すること。
- アプリ更新前後でデータの互換性を維持するため、データベース移行処理を設けること。
- エクスポートデータは暗号化またはパスワード保護を行わないため、利用者が保存先を確認できること、および第三者が閲覧可能な場所への保存を避けるよう案内すること。

### 10.7 セキュリティ・プライバシー

- 外部通信を行わないこと。フレームワークやライブラリによる解析、広告、クラッシュ報告および自動更新確認も無効化または導入しないこと。
- リリースAPKは、不要なネットワーク権限を要求しないこと。
- 給与と勤務に関するデータは端末外へ自動送信しないこと。
- OSまたはフレームワークのクラウドバックアップ機能によって、アプリデータが意図せず端末外へ保存されないようにすること。
- 不要なAndroid権限を要求しないこと。
- エラーメッセージに、不要な内部情報または端末情報を表示しないこと。
- エクスポートは利用者が明示的に実行した場合に限ること。
- 端末自体のロックや暗号化は利用者の端末設定に依存する。

### 10.8 ログ・診断

- アプリケーションの通常動作に関する永続ログは出力しない。
- 利用者へ必要な情報は画面上のメッセージとして表示する。
- 開発ビルドで診断情報を使用する場合も、リリースビルドでは無効化または最小化し、給与・勤務情報を出力しないこと。
- 初期リリースでは、利用者向けの診断情報表示または診断ファイル出力機能を設けない。

### 10.9 保守性・テスト容易性

- 給与計算ロジックはUIから独立した自動テストを実行できること。
- 設定の組み合わせ、締め日、月末、割増時間帯、複数割増および端数処理をテストできる構造とする。
- ドメインルールと技術固有処理の責務を分離すること。
- データ形式または計算ルールを変更した場合、その互換性と影響範囲を記録すること。
- 基本シフトの反映、重複判定および反映後の勤務記録の独立性を自動テストできること。

### 10.10 アクセシビリティ・表記

- 表示言語は日本語を基本とする。
- 金額は日本円として桁区切りを使用し、単位を明示する。
- 日付、曜日、時刻および給与期間を誤認しにくい表記にする。
- 文字サイズを拡大した場合でも、主要な情報と操作を利用できること。

## 11. 制約事項

- Android端末上で動作すること。
- 外部への通信を必要としないこと。
- Google Playを使用せず、APKを個別配布すること。
- 業務ロジックはC#を使用すること。
- オニオンアーキテクチャを採用すること。
- データは端末内に保存すること。
- 永続的なアプリケーションログは出力しないこと。
- 単一利用者向けとし、複数従業員管理を実装しないこと。

## 12. 前提条件

- 利用者は、提供元不明アプリのインストールを許可できるAndroid端末を使用する。
- 利用者または配布担当者は、APKを端末へ安全に受け渡せる。
- 利用者は、自身に適用される単価、割増、件数加算および締め日を把握している。
- 端末の紛失、故障またはアプリのアンインストールに備え、利用者が必要に応じてデータをエクスポートする。
- アプリは単一通貨として日本円を扱う。

## 13. 主要な利用シナリオ

### UC-01 初期設定を行う

1. 利用者がアプリを初めて起動する。
2. 締め日を設定する。
3. 使用するサービス種類と時間区分を確認または設定する。
4. 基本単価、割増および件数加算を設定する。
5. 必要に応じて、月額手当を設定する。
6. 必要に応じて、曜日ごとの基本シフトを設定する。
7. アプリが給与計算に必要な設定の不足を検証する。
8. 利用者が日々の入力を開始する。

### UC-02 基本シフトを勤務実績へ反映する

1. 利用者が曜日ごとの基本シフトを登録する。
2. 利用者がカレンダーから実績を登録する日付を選択する。
3. アプリが、その曜日の基本シフトを勤務入力へ自動的に反映し、登録予定の勤務記録および既存記録を表示する。
4. 利用者が内容を確認して登録を確定する。
5. アプリが基本シフトを通常の勤務記録として登録し、給与見込み額へ反映する。
6. 実際の勤務と異なる場合、利用者が作成された勤務記録を編集または削除する。

### UC-03 当日の勤務を登録する

1. 利用者がカレンダーから日付を選択する。
2. サービス種類と時間区分を選択する。
3. 必要な場合のみ時刻を入力する。
4. 利用者が保存する。
5. アプリが給与見込み額を計算する。
6. アプリが日別一覧と給与期間合計へ結果を反映する。

### UC-04 給与期間の見込み額を確認する

1. 利用者が対象の給与期間を選択する。
2. アプリが期間の開始日と終了日、合計額および内訳を表示する。
3. 利用者が日または勤務記録を選択する。
4. アプリが計算根拠を表示する。

### UC-05 端末を移行する

1. 利用者が旧端末でデータをエクスポートする。
2. 利用者が出力ファイルを安全な手段で新端末へ移す。
3. 利用者が新端末へアプリをインストールする。
4. 利用者が出力ファイルを選択してインポートする。
5. アプリがデータを検証し、取り込み内容を確認表示する。
6. 利用者が取り込みを確定する。
7. アプリが設定、基本シフト、勤務記録および給与計算結果を利用可能にする。

## 14. 初期リリースの受入条件

### AC-01 オフライン動作

ネットワークへ接続していないAndroid端末で、初期設定、基本シフトの登録・反映、勤務登録、給与計算、閲覧、エクスポートおよびインポートを実行できる。

### AC-02 設定

利用者がサービス種類、時間区分、基本単価、少なくとも休日・夜間の割増、1件当たりの件数加算、任意の月額手当および締め日を設定できる。

### AC-03 日々の入力

利用者が日付と勤務内容を登録し、登録直後に当日の給与見込み額を確認できる。

### AC-04 カレンダー

月間カレンダーで記録のある日を識別し、日付を選択して勤務記録と日合計を確認できる。

### AC-05 給与期間集計

設定した締め日に基づく期間の開始日と終了日が表示され、その期間に含まれる勤務記録と対象給与期間の月額手当だけを用いた合計額と内訳を確認できる。

### AC-06 計算根拠

各勤務記録について、適用された基本単価、割増および件数加算を確認できる。給与期間に月額手当が設定されている場合は、その表示名と金額を確認できる。

### AC-07 データ移行

旧端末相当の環境で出力したデータを新規環境へ取り込み、設定、基本シフトおよび勤務記録を復元できる。不正なファイルを指定しても既存データが失われない。

### AC-08 APK配布・更新

署名済みAPKをAndroid端末へ個別にインストールでき、同一署名の新バージョンへ更新しても既存データが保持される。

### AC-09 単一利用者

アカウント登録や従業員選択を必要とせず、起動後に本人の給与入力・確認を開始できる。

### AC-10 ログと通信

リリース版について、少なくとも次を検証できる。

- アプリ自身が外部通信を行わない。
- APKが不要なネットワーク権限を要求しない。
- OSまたはフレームワークによるアプリデータの自動クラウドバックアップが無効である。
- アプリが給与または勤務に関する永続ログを出力しない。

### AC-11 最小入力

給与設定の完了後、基本的な勤務記録は、単価、割増額、件数加算額および締め日を再入力せずに登録できる。時刻は、選択した計算設定で必要な場合に限り入力を求める。

### AC-12 計算テスト

実装前に合意した代表的な計算例について、基本給与、各割増額、件数加算額、月額手当、日別合計および給与期間合計が期待値と一致する。代表例には、締め日前後、月末、休日、夜間、日付をまたぐ勤務、複数条件の重複および端数処理を含める。

### AC-13 基本シフト

曜日ごとに複数の基本シフトを登録できる。日付を選択すると、その曜日の基本シフトが勤務入力へ自動的に反映され、利用者が登録を確定するまでは給与計算へ含まれない。登録前に作成内容と既存記録を確認でき、同じ内容を意図せず二重登録しない。登録後の勤務記録は個別に編集・削除でき、元の基本シフトを変更または削除しても変化しない。

### AC-14 性能

30年分、1日当たり最大20件、合計最大22万件の勤務記録を保持した代表端末で、勤務保存後の再計算、カレンダー表示および給与期間集計が操作開始から2秒以内に完了する。

## 15. 確認事項と決定内容

## 16. リスク

| ID | リスク | 影響 | 対応方針 |
| --- | --- | --- | --- |
| R-01 | 給与計算ルールの実装解釈が一致しない | 計算結果が期待と異なる | Q-01～Q-08の決定内容を具体的な計算例へ展開し、実装前に期待値を合意する |
| R-02 | UIとC#業務ロジックの境界が複雑になる | 開発・保守コスト増加 | Angularを採用せず、.NET MAUI XAMLからApplication層を直接参照する。依存方向を自動テストで検証する |
| R-03 | APK署名鍵を紛失する | 既存アプリを更新できない | 署名鍵とパスワードを安全にバックアップする運用を定める |
| R-04 | 端末故障やアンインストールでデータを失う | 過去データを復元できない | 定期的なエクスポートを画面で案内する |
| R-05 | 暗号化しないエクスポートファイルが第三者に閲覧される | 給与・勤務情報が漏えいする | 保存内容を移行に必要な情報へ限定し、実行前に保存先と取り扱い上の注意を表示する |
| R-06 | 設定変更で他の年月の計算結果が意図せず変わる | 過去結果を再現できない | 設定を年月単位で管理し、変更対象以外の年月へ反映しないことを自動テストする |
| R-07 | OS更新や端末差異でAPKが動作しない | 利用継続が困難になる | 対象OSを定義し、代表端末とエミュレーターで更新テストを行う |
| R-08 | 外部通信を行う依存ライブラリが混入する | オフライン要件・プライバシー違反 | 依存関係を棚卸しし、リリース版の通信を検証する |
| R-09 | 基本シフトを同じ日へ重複して反映する | 給与見込み額が過大になる | 反映元を識別し、反映前のプレビューと重複警告を設ける |

## 17. 要件の優先順位

初期リリースの優先順位は、MoSCoW法により次のように整理する。

### Must（必須）

- 単一利用者向けであること
- サービス種類、時間区分および基本単価の設定
- 休日・夜間などの割増設定
- 1件当たりの件数加算設定
- 任意の月額手当設定
- 締め日の設定
- 日々の勤務記録の登録、編集および削除
- カレンダーと日別一覧
- 給与期間ごとの給与見込み額と内訳
- オフライン動作と端末内保存
- エクスポートおよびインポート
- 署名済みAPKによる配布と更新
- C#による給与計算ロジック
- オニオンアーキテクチャ
- 外部通信および通常ログの不使用
- 曜日ごとの基本シフトの登録、反映
- 年月ごとの設定保持による過去計算の再現

### Should（優先度高）

- 直前値の再利用および勤務記録の日単位での複製
- よく使う勤務内容の定型登録
- 計算根拠の詳細表示
- 定期的なエクスポートの案内

### Could（可能であれば）

- 1日の記録の一括入力
- 横向き画面またはタブレットへの最適化

### Won't（初期リリースでは対象外）

- 複数従業員管理
- クラウド同期
- Google Play配布
- 事業所向け集計および承認
- 税金、社会保険料などの控除計算
- 基本シフトの複数日または給与期間への一括反映
- エクスポートデータの暗号化またはパスワード保護
- 利用者向け診断情報の表示または出力
