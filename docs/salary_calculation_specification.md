## 3. 計算入力と基本単位

### 3.1 訪問とタスク

給与計算へ渡す勤務記録は1件の訪問を表し、保存時に次を確定していること。

- 勤務日（訪問全体で共通のローカル日付）
- 1件以上のタスク

各タスクは、保存時に次を確定していること。

- タスクID
- サービス種類の論理ID
- 時間区分の論理ID（任意時間入力では未設定可）
- 給与計算対象となる勤務分数
- 開始時刻と終了時刻（時刻条件を持つ割増の判定に必要な場合）
- 訪問内の表示順

`開始・終了時刻`入力では、終了時刻が開始時刻より後なら同日、以前なら翌日とする。開始時刻と終了時刻が同じ場合は24時間勤務として扱う。勤務分数はタスクごとに時刻差から算出し、利用者に重複入力させない。

`勤務時間`入力ではタスクの勤務分数を利用者が指定する。時刻条件を持つ割増が対象サービスに存在する場合は開始時刻も入力し、終了時刻を`開始時刻 + 勤務分数`から算出する。各タスクの勤務分数は1分以上1,440分以内とする。

タスク間の時間の重複、空き、連続性および入力順との一致は検証せず、訪問内の合計勤務分数にも上限を設けない。開始・終了日時は給与期間を分割するためには使わない。日付をまたいでも全タスクを訪問の日付の給与期間へ含め、設定スナップショットも訪問の日付の年月から選択する。

### 3.2 金額と割合

- 金額は0以上の整数円とする。
- 時間は1分単位の整数とする。
- 割合はbasis pointの整数とし、100%を`10000`とする。
- 金額計算に浮動小数点数を使用しない。

### 3.3 切り上げ

非負整数`n`を正整数`d`で割って切り上げる処理を、次の`ceil_div`として共通化する。

```text
ceil_div(n, d) = (n + d - 1) / d の整数除算
```

本書で明示する各明細額を算出した時点で1円未満を切り上げる。すでに整数円となった明細同士の加算では追加の丸めを行わない。

## 4. 適用設定の選択

### 4.1 設定スナップショット

訪問の勤務日のカレンダー年月に対応する設定スナップショットを1つ選択し、訪問内の全タスクへ共通して使用する。日付をまたぐタスクでも訪問の日付の年月を使用する。

サービス種類と時間区分の`is_enabled`は新規入力の候補へ表示するかを表し、既存タスクの計算可否を表さない。タスクが参照するサービス種類や時間区分がスナップショット内に存在し、必要な単価があれば、無効状態でも既存タスクを計算する。

割増と件数加算の`is_enabled`は、そのルールを対象年月の計算へ適用するかを表す。無効な割増と件数加算は、新規勤務と既存勤務のどちらにも適用しない。

### 4.2 基本単価の選択順

基本単価はタスクごとに次の順で最大1件を選択する。

1. タスクに時間区分IDがあり、そのサービス種類と時間区分に一致する単価
2. サービス種類だけに一致し、時間区分IDが未設定の単価

1が存在する場合は2より優先する。同じ優先順位の単価が複数存在する構成は保存およびインポート時に拒否する。どちらも存在しない場合は勤務記録を未計算とし、不足している単価を表示する。

任意時間入力ではタスクに時間区分IDを持たせないため、サービス種類単位の単価だけを使用できる。固定額方式もサービス種類単位で設定されていれば任意時間入力へ適用できる。

## 5. 基本給与

### 5.1 時給方式

```text
基本給与 = ceil_div(時給額 × 勤務分数, 60)
```

例：時給1,001円、30分の場合は`ceil_div(1001 × 30, 60) = 501円`。

### 5.2 タスクごとの固定額方式

```text
基本給与 = 設定された固定額
```

タスクの勤務分数による増減は行わない。ただし、勤務分数は割増の時間按分と入力検証に使用する。

既存データとの互換性のため永続値`FixedPerRecord`は維持するが、スキーマ6以降の`Record`は訪問ではなく、その値を持つタスク1件を意味する。割増の`FixedPerRecord`も同様にタスク1件当たりとする。

## 6. 割増条件の判定

### 6.1 条件の組み合わせ

1つの割増ルール内では、条件を次のように評価する。

- 対象サービスが指定されている場合、サービス条件は一致必須とする。指定がなければ全サービスを対象とする。
- 曜日、国民の祝日、個別日付のうち複数が設定されている場合、いずれかに一致すれば日付条件を満たす。いずれも設定されていなければ全日を対象とする。
- 時間帯が設定されている場合、日付条件を満たす実時間区間と時間帯が重なる部分だけを対象とする。時間帯がなければ、日付条件を満たす勤務部分全体を対象とする。
- サービス条件と日付・時間条件はANDで結合する。

同じタスクについて、同じ割増ルールが曜日と祝日の両方に一致しても、そのルールは1回だけ計算する。異なる割増ルールはタスクごとにそれぞれ計算し、重複して加算する。

### 6.2 日付をまたぐ勤務

曜日、国民の祝日および個別日付は、勤務記録の`勤務日`、すなわち訪問の日付だけで判定する。タスクが日付をまたいでも途中で日付条件を切り替えない。これにより、勤務時間方式で時刻条件がない場合に不要な開始時刻を要求せず、訪問、給与期間および設定年月の日付基準を統一する。

例：訪問日が日曜日で、タスクが23:30から月曜日00:30までの場合は、日曜日を勤務日として休日条件を判定する。日曜日が休日なら、時間帯条件のない休日割増はタスク60分全体を対象とする。

### 6.3 時間帯

時間帯は開始を含み終了を含まない半開区間として扱う。

- 開始時刻より終了時刻が後：同日内の時間帯
- 終了時刻が開始時刻以前：翌日へまたぐ時間帯
- 開始時刻と終了時刻が同じ時間帯設定：無効な設定として保存しない

勤務区間と、日ごとに繰り返す時間帯との重なりを求め、重なった分数の合計をその割増ルールの`対象分数`とする。同じルールの時間帯が日付境界をまたいでも、重複する実時間を二重に数えない。

## 7. 割増額

割増条件を満たす実時間がない場合、その割増額は0円とする。

### 7.1 割合加算

まず対象分に対応する基本給与を算出し、その整数円へ割合を適用する。

```text
時給方式の対象基本給与
  = ceil_div(時給額 × 対象分数, 60)

固定額方式の対象基本給与
  = ceil_div(タスクの固定基本給与 × 対象分数, タスクの勤務分数)

割合割増額
  = ceil_div(対象基本給与 × 割合basis point, 10000)
```

対象時間帯がない割増では`対象分数 = 勤務分数`とする。

### 7.2 時間当たり固定額加算

```text
時間当たり固定額の割増額
  = ceil_div(1時間当たり加算額 × 対象分数, 60)
```

### 7.3 タスク1件当たり固定額加算

サービス条件と日付条件を満たし、時間帯条件がないか、時間帯と1分以上重なる場合に、設定額をタスクへ1回だけ加算する。時間按分は行わない。

## 8. 件数加算

有効な件数加算ルールごとに、訪問内のいずれかのタスクのサービス種類が対象なら設定額を訪問へ1回加算する。対象サービスが未指定のルールは全サービスを対象とし、タスクが1件以上あるすべての訪問へ1回適用する。

同じ件数加算ルールに一致するタスクが複数あっても1回だけ加算する。複数の異なる件数加算ルールに一致する場合は、各ルールを1回ずつ加算する。勤務記録1件を訪問1件とし、タスク数、勤務分数または日付をまたぐかどうかでは件数を増やさない。

## 9. 集計

```text
タスク給与
  = タスクの基本給与
  + タスクへ適用される割増ルールごとの割増額の合計

訪問合計
  = 訪問内のタスク給与の合計
  + 訪問へ適用される件数加算ルールごとの加算額の合計

日別合計
  = 勤務日が同じ訪問合計の合計

給与期間合計
  = 対象給与期間に属する日別合計の合計
  + 対象給与期間の月額手当の合計

年間給与見込み累計
  = 年間区分の開始給与期間から選択中給与期間までの給与期間合計の合計
```

タスク給与と訪問合計は、各明細ですでに整数円へ丸めた値を追加の丸めなしで、オーバーフローを検出する整数加算によって合計する。訪問合計が表現可能範囲を超える場合は部分結果を返さず計算エラーとする。月額手当は給与期間へ直接加算し、訪問、タスクまたは日へ配賦しない。未計算の訪問が1件以上ある場合、計算済み訪問の小計と未計算訪問数は表示してよいが、給与期間全体を確定的な合計として表示しない。

年間締め月は保存済み設定の1月から12月を使用し、未設定時は12月とする。年間区分は締め月で終了する連続12給与期間とし、選択中給与期間を累計終点として、それより後の給与期間を含めない。1回のホーム読取では処理開始時に年間締め月を1回取得し、同じ値を範囲と集計へ一貫して使用する。集計範囲は`PayrollPeriodKey`で決め、勤務記録の検索範囲は開始給与期間の実際の開始日から選択中給与期間の実際の終了日までとする。締め日が途中で変更されている場合、各給与期間には締め日履歴から求めた境界を使用する。

各給与期間について既存の給与期間集計を1回構築してから、給与期間キー順に年間累計へ加算する。未計算訪問は推測額へ含めず、年間範囲内の未計算訪問数を合算する。金額加算は`long`の範囲を超えた場合に失敗させ、部分的な年間結果を返さない。訪問が0件でも月額手当だけがある給与期間を含め、訪問と月額手当がともにない年間範囲は0円とする。

## 10. 保存可否と未計算

次は入力自体が不正なため保存しない。

- 訪問の日付が欠けている
- 訪問のタスクが0件である
- タスクIDが空、または同じ訪問内で重複している
- タスクの表示順が重複している、または0始まりの連番へ正規化できない
- いずれかのタスクでサービス種類または勤務分数が欠けている
- いずれかのタスクの勤務分数が1分未満または24時間を超える
- いずれかのタスクの時刻が範囲外である
- 時刻条件の判定に必要な開始時刻を入力していないタスクがある
- 時刻から算出した勤務分数と保存する勤務分数が一致しないタスクがある

入力は正しいが、1件以上のタスクで対象年月に単価がないなど計算設定だけが不足する場合は、タスクID付きの警告と不足内容を表示したうえで訪問全体の保存を許可する。保存後は訪問全体を未計算として扱い、計算可能なタスクだけの合計や件数加算を訪問合計として表示しない。診断用に計算可能なタスクの内訳を保持してよいが、未計算訪問の件数加算は空、訪問合計は未設定とする。これにより実績入力を失わず、後から設定を補って再計算できるようにする。

計算結果は訪問ID、訪問の計算状態、タスクIDごとの計算状態・適用単価・基本給与・割増・タスク小計、訪問へ適用した件数加算、訪問合計、およびタスクID付き不足理由を保持する。訪問内の全タスクが計算可能な場合だけ訪問を計算済みとする。

## 11. 決定例

| ID | 条件 | 期待結果 |
| --- | --- | --- |
| `EX-01` | 固定基本850円、全体30分、割合25%、対象15分 | 対象基本`ceil_div(850×15,30)=425円`、割増`ceil_div(425×2500,10000)=107円` |
| `EX-02` | 1件固定割増200円、時間帯との重なりが1分 | 200円を1回加算 |
| `EX-03` | 任意時間、サービス単位の時給1,200円、45分 | 基本給与900円 |
| `EX-04` | 22:00～05:00の割増、23:30～00:30勤務 | 対象60分 |
| `EX-05` | 日曜23:30～月曜00:30、日曜だけ休日、時間帯条件なし | 開始日の日曜で判定し、対象60分 |
| `EX-06` | 同じ訪問に身体1タスク1,000円、生活3タスク800円、全サービス対象の件数加算150円 | タスク給与1,000円と800円、件数加算1回150円、訪問合計1,950円。別々の訪問として登録した場合の2,100円にはしない |
| `EX-07` | 同じ件数加算の対象となる身体1タスクが同じ訪問に2件 | 件数加算は訪問へ1回だけ適用 |

## 12. 実装上の責務

- Domain層は、訪問を集約ルートとし、正規化済みの1件以上のタスク、設定スナップショットおよび祝日カレンダーを受け取り、副作用なしでタスク内訳、訪問の件数加算、訪問合計または未計算理由を返す。
- Application層は、訪問と全タスクの入力正規化、対象年月の設定取得、保存可否の判断、タスクID付きエラーパスおよび親子一括のトランザクション境界を扱う。
- Infrastructure層は、SQLiteとファイル形式の整数値をDomain/Applicationの値オブジェクトへ変換する。
- Presentation層は、計算式を再実装せず、Application層から返された明細と未計算理由を表示する。

## 13. 変更時の規則

計算式、丸め位置、条件結合または単価選択順を変更する場合は、次を同じ変更で更新する。

1. 本書と要件定義書
2. 設定履歴データモデルとデータベース仕様書
3. テスト仕様書の期待値
4. 必要に応じてエクスポート形式バージョンまたはDBスキーマバージョン
