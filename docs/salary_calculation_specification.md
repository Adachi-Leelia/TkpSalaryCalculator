## 3. 計算入力と基本単位

### 3.1 勤務記録

給与計算へ渡す勤務記録は、保存時に次を確定していること。

- 勤務日（勤務開始日のローカル日付）
- サービス種類の論理ID
- 時間区分の論理ID（任意時間入力では未設定可）
- 給与計算対象となる勤務分数
- 開始時刻と終了時刻（時刻条件を持つ割増の判定に必要な場合）

`開始・終了時刻`入力では、終了時刻が開始時刻より後なら同日、以前なら翌日とする。開始時刻と終了時刻が同じ場合は24時間勤務として扱う。勤務分数は時刻差から算出し、利用者に重複入力させない。

`勤務時間`入力では勤務分数を利用者が指定する。時刻条件を持つ割増が対象サービスに存在する場合は開始時刻も入力し、終了時刻を`開始時刻 + 勤務分数`から算出する。24時間を超える勤務記録は保存せず、複数の勤務記録へ分けるよう案内する。

開始・終了日時は給与期間を分割するためには使わない。日付をまたいでも勤務記録全体を開始日の給与期間へ含め、設定スナップショットも開始日の年月から選択する。

### 3.2 金額と割合

- 金額は0以上の整数円とする。
- 時間は1分単位の整数とする。
- 割合はbasis pointの整数とし、100%を`10000`とする。
- 金額計算に浮動小数点数を使用しない。

### 3.3 切り上げ

非負整数`n`を正整数`d`で割って切り上げる処理を、次の`ceil_div`として共通化する。

```text
ceil_div(n, d) = (n + d - 1) / d の整数除算
```

本書で明示する各明細額を算出した時点で1円未満を切り上げる。すでに整数円となった明細同士の加算では追加の丸めを行わない。

## 4. 適用設定の選択

### 4.1 設定スナップショット

勤務日のカレンダー年月に対応する設定スナップショットを1つ選択する。日付をまたぐ勤務でも開始日の年月を使用する。

サービス種類と時間区分の`is_enabled`は新規入力の候補へ表示するかを表し、既存勤務の計算可否を表さない。勤務記録が参照するサービス種類や時間区分がスナップショット内に存在し、必要な単価があれば、無効状態でも既存勤務を計算する。

割増と件数加算の`is_enabled`は、そのルールを対象年月の計算へ適用するかを表す。無効な割増と件数加算は、新規勤務と既存勤務のどちらにも適用しない。

### 4.2 基本単価の選択順

基本単価は次の順で最大1件を選択する。

1. 勤務記録に時間区分IDがあり、そのサービス種類と時間区分に一致する単価
2. サービス種類だけに一致し、時間区分IDが未設定の単価

1が存在する場合は2より優先する。同じ優先順位の単価が複数存在する構成は保存およびインポート時に拒否する。どちらも存在しない場合は勤務記録を未計算とし、不足している単価を表示する。

任意時間入力では勤務記録に時間区分IDを持たせないため、サービス種類単位の単価だけを使用できる。固定額方式もサービス種類単位で設定されていれば任意時間入力へ適用できる。

## 5. 基本給与

### 5.1 時給方式

```text
基本給与 = ceil_div(時給額 × 勤務分数, 60)
```

例：時給1,001円、30分の場合は`ceil_div(1001 × 30, 60) = 501円`。

### 5.2 勤務記録ごとの固定額方式

```text
基本給与 = 設定された固定額
```

勤務分数による増減は行わない。ただし、勤務分数は割増の時間按分と入力検証に使用する。

## 6. 割増条件の判定

### 6.1 条件の組み合わせ

1つの割増ルール内では、条件を次のように評価する。

- 対象サービスが指定されている場合、サービス条件は一致必須とする。指定がなければ全サービスを対象とする。
- 曜日、国民の祝日、個別日付のうち複数が設定されている場合、いずれかに一致すれば日付条件を満たす。いずれも設定されていなければ全日を対象とする。
- 時間帯が設定されている場合、日付条件を満たす実時間区間と時間帯が重なる部分だけを対象とする。時間帯がなければ、日付条件を満たす勤務部分全体を対象とする。
- サービス条件と日付・時間条件はANDで結合する。

同じ割増ルールが曜日と祝日の両方に一致しても、そのルールは1回だけ計算する。異なる割増ルールはそれぞれ計算し、重複して加算する。

### 6.2 日付をまたぐ勤務

曜日、国民の祝日および個別日付は、勤務記録の`勤務日`、すなわち開始日だけで判定する。日付をまたいでも途中で日付条件を切り替えない。これにより、勤務時間方式で時刻条件がない場合に不要な開始時刻を要求せず、勤務記録、給与期間および設定年月の日付基準を統一する。

例：日曜日23:30から月曜日00:30までの勤務は、日曜日を勤務日として休日条件を判定する。日曜日が休日なら、時間帯条件のない休日割増は勤務60分全体を対象とする。

### 6.3 時間帯

時間帯は開始を含み終了を含まない半開区間として扱う。

- 開始時刻より終了時刻が後：同日内の時間帯
- 終了時刻が開始時刻以前：翌日へまたぐ時間帯
- 開始時刻と終了時刻が同じ時間帯設定：無効な設定として保存しない

勤務区間と、日ごとに繰り返す時間帯との重なりを求め、重なった分数の合計をその割増ルールの`対象分数`とする。同じルールの時間帯が日付境界をまたいでも、重複する実時間を二重に数えない。

## 7. 割増額

割増条件を満たす実時間がない場合、その割増額は0円とする。

### 7.1 割合加算

まず対象分に対応する基本給与を算出し、その整数円へ割合を適用する。

```text
時給方式の対象基本給与
  = ceil_div(時給額 × 対象分数, 60)

固定額方式の対象基本給与
  = ceil_div(勤務記録の固定基本給与 × 対象分数, 勤務分数)

割合割増額
  = ceil_div(対象基本給与 × 割合basis point, 10000)
```

対象時間帯がない割増では`対象分数 = 勤務分数`とする。

### 7.2 時間当たり固定額加算

```text
時間当たり固定額の割増額
  = ceil_div(1時間当たり加算額 × 対象分数, 60)
```

### 7.3 勤務記録1件当たり固定額加算

サービス条件と日付条件を満たし、時間帯条件がないか、時間帯と1分以上重なる場合に、設定額を勤務記録へ1回だけ加算する。時間按分は行わない。

## 8. 件数加算

有効な件数加算ルールごとに、勤務記録のサービス種類が対象なら設定額を1回加算する。対象サービスが未指定のルールは全サービスを対象とする。

複数の件数加算ルールに一致する場合はすべて加算する。勤務記録1件を訪問1件とし、勤務分数や日付をまたぐかどうかでは件数を増やさない。

## 9. 集計

```text
勤務記録合計
  = 基本給与
  + 割増ルールごとの割増額の合計
  + 件数加算ルールごとの加算額の合計

日別合計
  = 勤務日が同じ勤務記録合計の合計

給与期間合計
  = 対象給与期間に属する日別合計の合計
  + 対象給与期間の月額手当の合計
```

月額手当は給与期間へ直接加算し、勤務記録または日へ配賦しない。未計算の勤務記録が1件以上ある場合、計算済み分の小計と未計算件数は表示してよいが、給与期間全体を確定的な合計として表示しない。

## 10. 保存可否と未計算

次は入力自体が不正なため保存しない。

- 日付、サービス種類または勤務分数が欠けている
- 勤務分数が1分未満または24時間を超える
- 時刻が範囲外である
- 時刻条件の判定に必要な開始時刻を入力していない
- 時刻から算出した勤務分数と保存する勤務分数が一致しない

入力は正しいが、対象年月に単価がないなど計算設定だけが不足する場合は、警告と不足内容を表示したうえで保存を許可する。保存後は未計算として扱い、推測した金額を表示しない。これにより実績入力を失わず、後から設定を補って再計算できるようにする。

## 12. 実装上の責務

- Domain層は、正規化済みの勤務記録、設定スナップショットおよび祝日カレンダーを受け取り、副作用なしで計算結果または未計算理由を返す。
- Application層は、勤務入力の正規化、対象年月の設定取得、保存可否の判断およびトランザクション境界を扱う。
- Infrastructure層は、SQLiteとファイル形式の整数値をDomain/Applicationの値オブジェクトへ変換する。
- Presentation層は、計算式を再実装せず、Application層から返された明細と未計算理由を表示する。

## 13. 変更時の規則

計算式、丸め位置、条件結合または単価選択順を変更する場合は、次を同じ変更で更新する。

1. 本書と要件定義書
2. 設定履歴データモデルとデータベース仕様書
3. テスト仕様書の期待値
4. 必要に応じてエクスポート形式バージョンまたはDBスキーマバージョン
