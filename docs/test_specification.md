## 2. 目的と関連文書

本書は、[要件定義書](requirements.md)の機能要件、非機能要件および受入条件を検証するためのテスト方針、テストデータ、主要テストケースおよび合格条件を定義する。

関連文書：

- [画面遷移・画面仕様書](screen_specification.md)
- [データベース仕様書](database_specification.md)
- [設定履歴データモデル](setting_history_data_model.md)
- 給与計算仕様書（作成予定）

給与計算仕様書が必要なケースは、本書で未確定ケースとして識別する。期待値が一意に決まらない状態で、実装結果を正解としてテストへ固定しない。

## 3. テスト対象と対象外

### 3.1 対象

- 初期設定
- サービス種類、時間区分、サービス設定および基本単価
- 割増、件数加算および月額手当
- 給与締め日と給与期間
- 年月別の設定スナップショット
- 基本シフトと定型勤務
- 勤務記録の登録、編集、複製および削除
- 日別・給与期間別の給与見込み額と内訳
- カレンダーと画面遷移
- SQLite保存とスキーママイグレーション
- エクスポートと全置換インポート
- オフライン動作、権限、バックアップおよびログ
- APKの新規インストールと更新インストール
- 性能、アクセシビリティおよびエラー復旧

### 3.2 対象外

- 複数利用者・複数従業員管理
- クラウド同期
- Google Play配布
- 税金、社会保険料および交通費などの控除計算
- 横向き・タブレット専用レイアウトの最適化
- エクスポートファイルの暗号化とパスワード保護
- 利用者向け診断情報の出力

## 4. テストレベル

| レベル | 主な対象 | 実行環境 | 自動化方針 |
| --- | --- | --- | --- |
| Domain単体 | 金額、分数、期間、給与計算、割増判定 | 通常の.NETテストプロジェクト | 必須 |
| Application単体 | ユースケース、入力検証、設定選択、重複判定 | テストダブルを使用 | 必須 |
| Infrastructure統合 | SQLite、トランザクション、マイグレーション、JSON入出力 | 一時SQLiteファイル | 必須 |
| Presentation単体 | ViewModel、画面状態、コマンド、エラー表示 | UIを起動しない.NETテスト | 主要フローを自動化 |
| Android UI | 画面遷移、入力、戻る操作、ファイル選択 | エミュレーターと代表端末 | 主要シナリオを自動化または手動確認 |
| リリース受入 | APK署名、更新、権限、通信、性能 | Release APKと代表端末 | 手動確認を含む |

DomainとApplicationのテストはAndroidや.NET MAUIへ依存させない。

## 5. テスト環境

### 5.1 必須環境

| 環境ID | 環境 | 用途 |
| --- | --- | --- |
| `ENV-DOTNET` | 実装で採用する安定版.NET SDK | 単体・統合テスト |
| `ENV-A29` | Android 10、API 29エミュレーター | 最低対応OS |
| `ENV-ACURRENT` | リリース時点の対応対象内で新しいAndroid | OS差異確認 |
| `ENV-DEVICE` | 利用予定の代表実機 | 性能、入力UI、更新、ファイル選択 |
| `ENV-OFFLINE` | 機内モードかつWi-Fi無効の代表実機 | オフライン受入 |

代表実機の機種、Androidバージョン、CPU、メモリおよび空き容量は、選定後に本書へ追記する。

### 5.2 ビルド種別

- 単体・統合テストはDebug相当で実行する。
- 通信、権限、ログ、バックアップ、署名、更新および性能は配布予定と同じRelease構成で確認する。
- 性能計測ではデバッガーを接続しない。

## 8. 給与計算テスト

### 8.1 現行要件から期待値を確定できるケース

すべての金額は整数円とし、割り算で端数が発生した時点で切り上げる。

| ID | 優先度 | 条件 | 期待結果 |
| --- | --- | --- | --- |
| `CALC-001` | P0 | 固定額方式850円、勤務1件 | 基本給与850円 |
| `CALC-002` | P0 | 時給1,200円、勤務30分 | 基本給与600円 |
| `CALC-003` | P0 | 時給1,001円、勤務30分 | 500.5円を切り上げ、基本給与501円 |
| `CALC-004` | P0 | 基本給与501円、割合割増25%、全勤務が対象 | 125.25円を切り上げ、割増126円、合計627円 |
| `CALC-005` | P0 | 時間当たり固定額301円、対象時間30分 | 150.5円を切り上げ、割増151円 |
| `CALC-006` | P0 | 1件固定額200円の割増条件を満たす勤務1件 | 割増200円を1回加算 |
| `CALC-007` | P0 | 基本1,200円、休日25%で300円、夜間200円/時の対象30分で100円、件数加算150円 | 勤務記録合計1,750円 |

### 8.3 給与計算仕様書で確定後に追加するケース

| 仮ID | 未確定事項 | 必要な決定 |
| --- | --- | --- |
| `CALC-P01` | 固定額方式の勤務の一部だけが割合割増時間帯に該当 | 基本給与の按分方法と丸め順序 |
| `CALC-P02` | 1件固定額割増の勤務の一部だけが時間帯条件に該当 | 全額1回か時間按分か |

これらは給与計算機能の完了判定を妨げるP0仕様課題とする。

## 22. リリース合格条件

- `AC-01`～`AC-14`へ対応するP0テストがすべて成功している。
- 未確定の`CALC-P01`～`CALC-P07`が給与計算仕様書で解消され、対応テストが成功している。
- P0障害が0件である。
- P1障害は、利用者の給与額、データ保全、オフライン要件および更新継続性へ影響しないと確認されている。
- API 29環境と代表実機で主要利用シナリオが成功している。
- 22万件データでP0性能条件を満たしている。
- Release APKの署名、権限、通信、バックアップおよび更新テストが成功している。
- 旧データのマイグレーションとエクスポート／インポートの往復で計算結果が一致している。

## 23. 障害の重要度

| 重要度 | 基準 |
| --- | --- |
| Critical | データ消失、給与額の重大な誤り、起動不能、更新不能、意図しない外部通信 |
| High | 主要機能を完了できない、過去計算を再現できない、回避困難な誤表示 |
| Medium | 回避手段がある機能不良、限定条件の画面崩れ、性能劣化 |
| Low | 文言、配置、軽微な操作性の問題 |

## 24. 残課題

- `CALC-P01`～`CALC-P07`を解消する給与計算仕様書を作成する。
- 代表実機を選定し、性能試験条件を確定する。
- Android UIテストで使用する自動化方式を選定する。
- 本番署名、配布、更新および署名鍵バックアップの運用手順を定義する。
- エクスポート形式の正式なJSON Schemaと互換性テストデータを作成する。
- 初回リリース後のスキーママイグレーション試験用に、リリース版ごとのDBフィクスチャを保管する。
