## 2. 依頼内容と背景

実績を登録するときに、件数手当をON（加算する）またはOFF（加算しない）にできるようにする。

既存仕様では件数手当を「件数加算」と呼ぶ。本書でも同じものとして扱う。現行の計算は、訪問日の設定と訪問内のサービス種類に適合した件数加算を自動適用する。勤務記録に加算有無の項目がないため、一部の実績だけを加算対象から外せない。

例えば、身体1のタスク給与1,000円と生活3のタスク給与800円を持つ訪問に、150円の件数加算が適用される場合、ONでは1,950円、OFFでは1,800円にする。

## 3. 要求と仕様案の区別

利用者の明示要求は「実績登録時に件数手当のON／OFFを選択できること」である。以下は、既存の訪問単位の計算と過去データの互換性を保つために本書で置く仕様案とする。

| 論点 | 本書の仕様案 |
| --- | --- |
| 選択単位 | 実績1件（訪問）につき1つ。訪問内の全タスクに共通 |
| 複数の件数加算ルール | OFFではすべて除外。ONでは従来の適用条件を満たす各ルールを1回ずつ加算 |
| 新規登録の初期値 | ON。直前の登録で選択したOFFを次の新規登録へ引き継がない |
| 既存実績・旧形式データ | ONを補い、従来の計算結果を維持 |
| 登録済み実績 | 編集時も切替可能。保存済みの選択を初期表示 |
| 日単位複製 | 複製元の訪問ごとのON／OFFを維持 |
| 基本シフトから登録 | 反映候補ごとにONを初期値として選択可能。確定前の選択を実績へ保存 |

初期値、複数ルールの一括制御、基本シフト反映時の選択方法は利用者が個別に指定した事項ではない。変更する場合は本書と関連仕様の整合を取る。

## 4. 機能要件

### 4.1 登録・編集画面

- `SCR-WORK-01`の訪問共通項目として、勤務日の近くに「件数手当を加算する」スイッチを1つ配置する。
- ONは「加算する」、OFFは「加算しない」と文字でも示す。補足として「この実績の件数手当すべてに適用します。金額は当日の設定で計算します。」と表示する。
- タスクの追加・編集・並べ替え・削除、サービス設定の選択、勤務日の変更で選択値をリセットしない。
- ON／OFFの変更を未保存変更として扱い、既存の離脱確認と保存処理へ含める。
- 切替後は既存のプレビュー処理で件数加算と訪問合計を再計算する。連続操作や日付変更で、遅れて完了した古い計算結果が最新状態を上書きしない。
- 適用可能な件数加算ルールがない場合も選択値を保持する。ONは設定に従う指定であり、必ず金額が加算される指定ではない。
- 保存は訪問、選択値、全タスクを1操作で確定する。キャンセル時や保存失敗時に選択値だけをDBへ反映しない。

### 4.2 計算と内訳

```text
ON ：従来の条件を満たす件数加算ルールを、訪問へ各1回適用
OFF：適用済み件数加算の一覧を空とし、計算可能な訪問の件数加算額を0円とする

訪問合計 = 全タスクの給与合計 + 件数加算額
```

- 基本給与、休日・夜間などの割増、月額手当の計算規則は維持する。OFFの訪問も実績件数と勤務時間に含める。
- ONでも無効なルールや対象サービスが一致しないルールを強制適用しない。同一ルールの対象タスクが複数あっても加算は1回とする。
- 選択値は給与設定の有効／無効とは独立する。給与設定を変更しても実績の選択値を変更しない。OFFの訪問に対する件数加算設定の変更は給与差額を生じさせない。
- 勤務日を変更した場合は選択値を維持し、変更先の勤務日の設定で再計算する。
- 未計算の判定は従来どおりとする。単価不足などの訪問をOFFにしても計算済みにはしない。未計算訪問では訪問合計を表示しない。
- 登録時のプレビューと`SCR-CALC-01`の内訳に、OFFの場合は「件数手当：加算しない」を表示する。計算可能な場合のみ0円を併記し、ONで適用ルールがない状態と区別する。
- 保存後は日別一覧・カレンダー、給与期間の内訳・合計、ホームの月次・年間累計を既存の更新経路で更新する。

### 4.3 複製と基本シフト反映

- 日単位複製では各訪問のON／OFFを引き継ぎ、訪問IDとタスクIDは既存仕様どおり新規採番する。金額は複製先の日付の設定で計算する。
- 基本シフト反映の確認画面では、登録予定の訪問ごとに同じスイッチを表示し、初期値をONとする。OFFへ切り替えた候補も確定するまで保存・給与集計しない。
- 基本シフト本体へ既定のON／OFFを保存する機能は今回の対象外とする。反映後の実績は通常の編集画面で変更できる。
- 二重登録防止の既存の類似判定は維持する。手当の選択だけが異なる同じ勤務内容も、重複候補として扱う。
- 複製・反映のプレビューと確定処理で選択値を一貫して使用する。確認トークンや冪等性判定で勤務内容を比較する箇所では、選択値の変更を取りこぼさない。

## 5. データと互換性

### 5.1 勤務記録

| 層 | 追加項目案 | 内容 |
| --- | --- | --- |
| Domain／Application | `WorkRecord.IsCountBonusEnabled`および関連DTO・コマンドの同名項目 | 必須の真偽値。初期化と旧データ変換で明示的にtrueを設定 |
| SQLite | `work_record.is_count_bonus_enabled` | `INTEGER NOT NULL DEFAULT 1 CHECK (is_count_bonus_enabled IN (0, 1))` |
| エクスポート | `workRecords`の`isCountBonusEnabled` | JSONの必須boolean |

選択値は訪問親に保持し、`work_task`、基本シフト、設定スナップショットへは追加しない。単価・件数加算額・計算結果を実績へ保存しない既存方針を維持する。

### 5.2 DB移行

- 調査時点のDBスキーマは6。次の移行として6→7を追加する案とする。実装開始時に別の移行が追加されていれば採番を調整する。
- 既存の全勤務記録へONを補い、過去の件数加算・日別合計・給与期間合計・年間累計を変化させない。
- 新規DB、旧版からの連続移行、既に移行済みのDBの再起動を扱う。移行失敗時はトランザクションをロールバックし、既存仕様の復旧動作に従う。
- 設定スナップショットのスキーマ版は変更しない。

### 5.3 エクスポート・インポート

- 調査時点のエクスポート形式は3。新形式4で選択値を必須化する案とする。OFFを含め必ず出力する。
- 形式1～3のインポートでは各勤務記録をONへ変換する。形式1・2の親子変換と形式1の年間締め月補完も維持する。
- 形式4で選択値が欠落、null、文字列または数値の場合は不正として、既存DBを変更する前に拒否する。非対応の将来形式も拒否する。
- 新形式の往復でON／OFF、訪問・タスク構造、計算結果を再現する。形式3への出力によってOFFを失う互換出力は設けない。
- 全置換の確認、逐次入出力、有界メモリ、取消・失敗時の既存データ保持という既存要件を維持する。

### タスク4の実装記録（2026-09-21）

- 通常の登録・編集は`SaveWorkRecordCommand.IsCountBonusEnabled`をプレビューと保存へ渡し、読取・再編集では保存済みの`WorkRecordDto`を返す。同じ保存操作IDで選択だけが異なる場合も、処理中・保存済みの両方で競合とする。
- 日単位複製は選択を維持して訪問ID・全タスクIDを新規採番する。`CopyDayConfirmationToken.SourceContentFingerprint`で元訪問・全タスク・選択値の変更を検出し、変更時は再プレビューを要求する。
- 基本シフトは`PreviewForDateAsync`の`countBonusSelections`と`ApplyBasicShiftsCommand.CountBonusSelections`へ候補IDごとの選択を渡す。省略した候補はON。候補の`Calculation`と`IsCountBonusEnabled`を確認表示に使用し、同じ辞書と返された`ConfirmationToken`を確定へ渡す。選択を指定する新経路では確認値を必須とする。選択・確認値を省略する既存呼出しは従来どおり全候補ONとして扱う。
- 確認値には候補内容・選択・既存訪問・対象日設定を含める。類似する手入力勤務の判定には選択を含めない。未確定月の祝日版もプレビューと確定で一致させる。失敗時は選択・訪問・タスク・月設定・変更日時を一括ロールバックする。
