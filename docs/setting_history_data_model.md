# 設定履歴データモデル

## 1. 文書情報

| 項目 | 内容 |
| --- | --- |
| 文書名 | 設定履歴データモデル |
| ステータス | 初期リリース向け設計方針 |
| 対象 | 基本単価、割増、件数加算、締め日および月額手当の履歴管理 |
| 作成日 | 2026-08-15 |

## 2. 目的

設定を変更した年月以外の給与計算結果を変化させず、過去の勤務記録と当時の設定から給与見込み額を再計算できるようにする。

本書では論理データモデルと更新規則を定義する。物理テーブル名、SQLiteのDDL、インデックスおよびマイグレーション手順の詳細は、データベース実装時に本書と矛盾しないように定義する。

## 3. 設計方針

### 3.1 年月別の設定スナップショット

基本単価、割増および件数加算は、年月ごとの変更不可な設定スナップショットとして管理する。

```text
設定対象年月 ──参照──> 設定スナップショット
                         ├─ サービス種類
                         ├─ 時間区分
                         ├─ 基本単価
                         ├─ 割増ルール
                         ├─ 件数加算
                         └─ 休日判定に使用する祝日データの版
```

- 1つの設定スナップショットを複数の年月から参照してよい。
- 作成済みの設定スナップショットは更新しない。
- ある年月の設定を変更するときは、現在のスナップショットを複製して変更後のスナップショットを作成し、その年月だけを新しいスナップショットへ付け替える。
- 他の年月からの参照は変更しない。
- 初期リリースでは、基本単価、割増および件数加算の変更を複数月へ一括反映する機能を設けない。

有効開始日と有効終了日だけで設定履歴を管理する方式は採用しない。「選択した1か月だけ変更」するたびに期間の分割が必要となり、期間の重複や空白が生じやすいためである。

### 3.2 設定を選択する年月

勤務記録の基本単価、割増および件数加算は、給与期間ではなく、勤務日のカレンダー年月に対応する設定スナップショットから取得する。

給与期間が月をまたぐ場合は、同じ給与期間内でも勤務日ごとに異なる年月の設定を使用できる。

```text
給与期間: 2026-07-21 ～ 2026-08-20

2026-07-21の勤務 → 2026年7月の設定
2026-08-10の勤務 → 2026年8月の設定
```

日付をまたぐ勤務では、要件定義に従い開始日を勤務日とし、開始日の年月に対応する設定を使用する。

### 3.3 締め日履歴の分離

締め日の変更は「指定した月以降」へ適用されるため、「指定した月だけ」へ適用する給与計算設定とは別に、有効開始年月を持つ履歴として管理する。

月額手当は勤務日の年月ではなく、対象給与期間へ直接関連付ける。

### 3.4 計算結果は原則として保存しない

日別合計および給与期間合計は、勤務記録と参照中の設定から再計算する。性能上キャッシュする場合も、キャッシュを削除して再構築できるようにし、正本として扱わない。

勤務記録には設定スナップショットIDを固定保存しない。利用者が対象年月の設定を意図的に変更した場合に、その年月の勤務記録を新しい設定で再計算できるようにするためである。

## 4. 論理データモデル

### 4.1 全体の関連

```text
SettingMonth ───────> SettingSnapshot
                           │
                           ├── SnapshotService ─────> ServiceDefinition
                           ├── SnapshotTimeCategory > TimeCategoryDefinition
                           ├── SnapshotRate
                           ├── SnapshotPremium
                           └── SnapshotCountBonus

WorkRecord ─────────> ServiceDefinition
     │                TimeCategoryDefinition（任意）
     └─ work_dateからSettingMonthを選択

ClosingRuleHistory ── effective_from_year_month以降の給与期間に適用
MonthlyAllowance ────> PayrollPeriodKey
```

### 4.2 年月とスナップショット

#### `setting_month`

| 項目 | 内容 |
| --- | --- |
| `year_month` | 対象年月。`YYYY-MM`相当の年月値オブジェクトを使用する。主キー |
| `snapshot_id` | 対象年月で使用する設定スナップショット |
| `created_at` | この年月の設定を初めて確定した日時 |
| `updated_at` | 参照先スナップショットを最後に変更した日時 |

`year_month`は端末のタイムゾーンに依存する日時ではなく、年と月だけを表す値として保持する。

#### `setting_snapshot`

| 項目 | 内容 |
| --- | --- |
| `id` | スナップショットID。主キー |
| `based_on_id` | 複製元のスナップショットID。初期スナップショットでは未設定 |
| `holiday_calendar_version_id` | 国民の祝日判定に使用するデータの版 |
| `schema_version` | スナップショット構造のバージョン |
| `created_at` | 作成日時 |

`based_on_id`は調査用の系譜であり、給与計算時には参照しない。計算に必要な設定は各スナップショット内で完結させる。

### 4.3 論理ID

サービス種類、時間区分、割増および件数加算には、表示名や設定値が変わっても変化しない論理IDを付与する。

| エンティティ | 論理IDの用途 |
| --- | --- |
| `service_definition` | 同じサービス種類を年月をまたいで識別する |
| `time_category_definition` | 同じ時間区分を年月をまたいで識別する |
| `premium_definition` | 同じ割増ルールを年月をまたいで識別する |
| `count_bonus_definition` | 同じ件数加算を年月をまたいで識別する |

表示名、標準時間、金額、適用条件および有効状態は論理ID側へ持たせず、設定スナップショット側へ保存する。

### 4.4 スナップショット内の設定

#### `snapshot_service`

| 項目 | 内容 |
| --- | --- |
| `snapshot_id` | 所属する設定スナップショット |
| `service_id` | サービス種類の論理ID |
| `display_name` | 表示名 |
| `display_order` | 表示順 |
| `is_enabled` | 対象年月で選択可能か |

主キーは`snapshot_id`と`service_id`の組み合わせとする。

#### `snapshot_time_category`

| 項目 | 内容 |
| --- | --- |
| `snapshot_id` | 所属する設定スナップショット |
| `time_category_id` | 時間区分の論理ID |
| `service_id` | 所属するサービス種類の論理ID |
| `display_name` | 表示名 |
| `standard_minutes` | 標準所要時間。整数分 |
| `display_order` | 表示順 |
| `is_enabled` | 対象年月で選択可能か |

任意時間を入力する勤務では、勤務記録の実勤務分数を使用する。時間区分を使用しない入力を許可する場合、`work_record.time_category_id`は未設定とする。

#### `snapshot_rate`

| 項目 | 内容 |
| --- | --- |
| `snapshot_id` | 所属する設定スナップショット |
| `service_id` | 対象サービス種類 |
| `time_category_id` | 対象時間区分。サービス種類単位の単価では未設定を許容 |
| `rate_type` | `Hourly`または`FixedPerRecord` |
| `amount_yen` | 整数円の単価 |

同じスナップショット内で適用対象が重複しないよう、一意制約を設ける。具体的な単価選択の優先順位と任意時間入力時の扱いは、給与計算仕様書で定義する。

#### `snapshot_premium`

| 項目 | 内容 |
| --- | --- |
| `snapshot_id` | 所属する設定スナップショット |
| `premium_id` | 割増の論理ID |
| `display_name` | 表示名 |
| `calculation_type` | `Percentage`、`FixedPerHour`または`FixedPerRecord` |
| `percentage_basis_points` | 割合加算値。割合方式の場合のみ使用 |
| `amount_yen` | 固定額。固定額方式の場合のみ使用 |
| `start_time_minutes` | 対象時間帯の開始。0時からの整数分。未指定可 |
| `end_time_minutes` | 対象時間帯の終了。0時からの整数分。未指定可 |
| `uses_national_holidays` | 国民の祝日を条件に含めるか |
| `is_enabled` | 対象年月で使用するか |

対象曜日、個別日付および対象サービス種類は、それぞれ子テーブルで複数保持する。

- `snapshot_premium_weekday`
- `snapshot_premium_date`
- `snapshot_premium_service`

割合は浮動小数点数ではなく整数のbasis pointで保持する。例えば25%は`2500`とする。計算式と丸め位置は給与計算仕様書で定義する。

#### `snapshot_count_bonus`

| 項目 | 内容 |
| --- | --- |
| `snapshot_id` | 所属する設定スナップショット |
| `count_bonus_id` | 件数加算の論理ID |
| `display_name` | 表示名 |
| `amount_yen` | 勤務記録1件当たりの整数円 |
| `is_enabled` | 対象年月で使用するか |

対象サービス種類は`snapshot_count_bonus_service`で複数保持する。対象サービスが登録されていない場合は全サービスを対象とする。

### 4.5 締め日履歴

#### `closing_rule_history`

| 項目 | 内容 |
| --- | --- |
| `id` | 締め日履歴ID |
| `effective_from_year_month` | この締め日を適用し始める給与期間年月 |
| `closing_day` | 1から31。月末締めでは未設定 |
| `is_end_of_month` | 月末締めか |
| `created_at` | 作成日時 |

対象の給与期間年月以下で、`effective_from_year_month`が最も新しいレコードを適用する。給与期間年月は、その給与期間の終了日が属する年月とする。

給与期間の終了日は対象月の締め日、開始日は前の給与期間の終了日の翌日とする。指定日が存在しない月は月末を終了日とする。

### 4.6 月額手当

#### `monthly_allowance`

| 項目 | 内容 |
| --- | --- |
| `id` | 月額手当ID |
| `payroll_period_year_month` | 対象給与期間の年月キー |
| `display_name` | 表示名 |
| `amount_yen` | 整数円 |

月額手当は設定スナップショットへ含めず、給与期間へ直接関連付ける。同じ給与期間に複数の月額手当を登録できる構造とする。

### 4.7 勤務記録との関連

`work_record`は少なくとも次の値を保持する。

| 項目 | 内容 |
| --- | --- |
| `id` | 勤務記録ID |
| `work_date` | 勤務開始日のローカル日付 |
| `service_id` | サービス種類の論理ID |
| `time_category_id` | 時間区分の論理ID。任意時間入力では未設定可 |
| `work_minutes` | 給与計算対象となる整数分 |
| `start_time_minutes` | 必要な場合の開始時刻 |
| `end_time_minutes` | 必要な場合の終了時刻 |
| `source_basic_shift_id` | 基本シフトから作成した場合の反映元識別子 |

勤務記録のサービス種類または時間区分が対象年月の設定スナップショットに存在しない場合や無効な場合は、別の設定へ自動変換しない。未計算として不足設定を利用者へ表示する。

基本シフト自体は現在の内容だけを保持し、設定スナップショットには含めない。基本シフトから確定済み勤務記録を作成した後は、元の基本シフトを変更しても勤務記録を変更しない。

### 4.8 祝日データ

国民の祝日データはアプリ更新によって変更される可能性があるため、版を識別できる構造にする。

| テーブル | 内容 |
| --- | --- |
| `holiday_calendar_version` | データ版、出典、参照日 |
| `holiday_date` | データ版、日付、祝日名 |

設定スナップショットは使用する祝日データ版を参照する。アプリ更新で祝日データを追加しても、作成済み年月の参照先を暗黙に変更しない。

## 5. 更新処理

### 5.1 新しい年月を初めて使用する場合

1. 対象年月の`setting_month`を検索する。
2. 存在しない場合は、対象年月より前で最も新しい`setting_month`を取得する。
3. 直近月と同じスナップショットを参照する`setting_month`を作成する。
4. 直近月が存在しない場合は、初期設定から作成した初期スナップショットを参照する。

この処理は、対象年月へ勤務を初めて登録するとき、または対象年月の設定画面を初めて確定するときにトランザクション内で実行する。単にカレンダーを閲覧しただけでは作成しなくてよい。

### 5.2 選択年月の設定を変更する場合

1. 対象年月の`setting_month`を作成または取得する。
2. 現在参照している設定スナップショット全体を複製する。
3. 複製先へ利用者の変更を適用する。
4. 複製先の参照整合性と計算可能性を検証する。
5. `setting_month.snapshot_id`を複製先へ付け替える。
6. 影響する対象年月の計算キャッシュがあれば無効化する。
7. 以上を1つのデータベーストランザクションで確定する。

検証または保存に失敗した場合は、参照先を変更しない。

### 5.3 締め日を変更する場合

1. 利用者が適用開始となる給与期間年月を指定する。
2. `closing_rule_history`へ新しい履歴を追加する。
3. 適用開始月より前の履歴は変更しない。
4. 適用開始月以降の給与期間キャッシュがあれば無効化する。
5. 対象となる勤務記録の所属給与期間と集計額を再計算する。

同じ適用開始年月の履歴がすでに存在する場合は、その行を直接更新せず、置換処理をトランザクションとして扱う。変更履歴自体の監査保存は初期リリースの対象外とする。

## 6. 削除と無効化

- 勤務記録または基本シフトから参照されている論理IDは物理削除しない。
- 利用者がサービス種類、時間区分、割増または件数加算を削除した場合は、新しい設定スナップショットで`is_enabled = false`とする。
- 無効化前に作成された他の年月の設定スナップショットは変更しない。
- 対象年月に既存の勤務記録がある場合は、計算不能になる変更を保存前に警告する。
- 利用者が変更を確定した結果として計算不能になった勤務記録は、推測値を使用せず未計算として表示する。

## 7. エクスポートとインポート

### 7.1 エクスポート対象

- すべての`setting_month`
- `setting_month`から参照される設定スナップショットとその子データ
- 参照されるサービス種類、時間区分、割増および件数加算の論理ID
- 締め日履歴
- 月額手当
- 基本シフト
- 勤務記録
- 使用中の祝日データ版を識別または再現するために必要な情報
- エクスポート形式およびスキーマのバージョン

どの年月からも参照されていない古いスナップショットは、給与計算の再現に不要なためエクスポート対象外としてよい。

### 7.2 インポート時の検証

- すべての年月が存在する設定スナップショットを参照していること。
- スナップショット内の論理ID参照が解決できること。
- 同じスナップショット内で単価や適用条件が不正に重複していないこと。
- 締め日履歴の適用開始年月が重複していないこと。
- 金額が整数円であり、分数、日付および時刻が許容範囲内であること。
- データ形式とスキーマのバージョンが対応範囲内であること。

検証完了後に全データを1つのトランザクションで置換する。途中で失敗した場合は既存データを維持する。

## 8. 整合性と実装上の制約

- 金額、勤務分数および割合の内部表現に浮動小数点数を使用しない。
- 外部キー制約を有効にする。
- スナップショットの子データは作成完了後に更新または削除しない。
- `setting_month`の参照先変更とスナップショット作成は同一トランザクションで行う。
- 給与計算は`WorkRecord + SettingSnapshot + HolidayCalendar`を入力とする副作用のない処理として実装する。
- 勤務記録の日付を変更した場合は、変更後の勤務年月の設定スナップショットを使用して再検証・再計算する。
- 未参照スナップショットの物理削除は必須機能としない。実施する場合は、どの年月からも参照されていないことをトランザクション内で確認する。

## 9. 自動テストで確認する事項

- 1か月の設定変更が他の年月の設定および計算結果を変えない。
- 同じスナップショットを参照する2か月の一方を変更すると、変更した月だけが新しいスナップショットを参照する。
- 月をまたぐ給与期間で、各勤務日のカレンダー年月に対応する設定が使われる。
- 日付をまたぐ勤務で開始日の年月に対応する設定が使われる。
- 締め日変更が指定した給与期間年月以降だけへ反映される。
- 対象月に存在しない締め日は月末として扱われる。
- 設定変更後も変更対象外の過去月を同じ結果で再計算できる。
- 無効化したサービス種類を参照する過去月の勤務記録を、その月の旧設定で再計算できる。
- インポート失敗時に既存の設定履歴と勤務記録が変化しない。
- エクスポート後に別のデータベースへインポートしても、年月ごとの計算結果が一致する。

## 10. 本書で確定しない事項

次の事項は給与計算仕様書または物理データベース設計で定義する。

- 時給、割合割増および時間当たり固定額の具体的な計算式と端数処理位置
- 任意時間入力に対する単価の選択規則
- 時間帯をまたぐ勤務に対する割増の按分方法
- 設定入力値の上限および下限
- SQLiteのDDL、インデックスおよびデータベースマイグレーション手順
- 計算キャッシュを導入するかどうか
