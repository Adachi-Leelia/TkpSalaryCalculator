# 設定履歴データモデル

## 1. 文書情報

| 項目 | 内容 |
| --- | --- |
| 文書名 | 設定履歴データモデル |
| ステータス | 初期リリース向け設計方針 |
| 対象 | 基本単価、割増、件数加算、締め日および月額手当の履歴管理 |
| 作成日 | 2026-08-15 |
| 最終更新日 | 2026-08-30 |

## 2. 目的

設定を変更した年月以外の給与計算結果を変化させず、過去の勤務記録と当時の設定から給与見込み額を再計算できるようにする。

本書では論理データモデルと更新規則を定義する。物理設計は[データベース仕様書](database_specification.md)、演算規則は[給与計算仕様書](salary_calculation_specification.md)で定義する。

## 3. 設計方針

### 3.1 年月別の設定スナップショット

基本単価、割増および件数加算は、年月ごとの変更不可な設定スナップショットとして管理する。

```text
設定対象年月 ──参照──> 設定スナップショット
                         ├─ サービス種類
                         ├─ 時間区分
                         ├─ 基本単価
                         ├─ 割増ルール
                         ├─ 件数加算
                         └─ 休日判定に使用する祝日データの版
```

- 1つの設定スナップショットを複数の年月から参照してよい。
- 作成済みの設定スナップショットは更新しない。
- ある年月の設定を変更するときは、現在のスナップショットを複製して変更後のスナップショットを作成し、その年月だけを新しいスナップショットへ付け替える。
- 他の年月からの参照は変更しない。
- 初期リリースでは、基本単価、割増および件数加算の変更を複数月へ一括反映する機能を設けない。

有効開始日と有効終了日だけで設定履歴を管理する方式は採用しない。「選択した1か月だけ変更」するたびに期間の分割が必要となり、期間の重複や空白が生じやすいためである。

### 3.2 設定を選択する年月

訪問内の全タスクの基本単価・割増と、訪問の件数加算は、給与期間ではなく、訪問の勤務日のカレンダー年月に対応する同じ設定スナップショットから取得する。

給与期間が月をまたぐ場合は、同じ給与期間内でも勤務日ごとに異なる年月の設定を使用できる。

```text
給与期間: 2026-07-21 ～ 2026-08-20

2026-07-21の勤務 → 2026年7月の設定
2026-08-10の勤務 → 2026年8月の設定
```

日付をまたぐタスクでも、要件定義に従い訪問の日付を勤務日とし、その年月に対応する設定を使用する。

### 3.3 締め日履歴の分離

締め日の変更は「指定した月以降」へ適用されるため、「指定した月だけ」へ適用する給与計算設定とは別に、有効開始年月を持つ履歴として管理する。

月額手当は勤務日の年月ではなく、対象給与期間へ直接関連付ける。

### 3.4 計算結果は原則として保存しない

日別合計および給与期間合計は、勤務記録と参照中の設定から再計算する。性能上キャッシュする場合も、キャッシュを削除して再構築できるようにし、正本として扱わない。

年間給与見込み累計も、対象となる給与期間合計から都度再構築し、正本として保存しない。年間締め月は現在値を独立した単一行設定として保存し、設定スナップショットまたは締め日履歴へ混在させない。変更履歴は作成せず、変更は過去データを改変せずに表示上の年間区分へ直ちに反映する。

勤務記録には設定スナップショットIDを固定保存しない。利用者が対象年月の設定を意図的に変更した場合に、その年月の勤務記録を新しい設定で再計算できるようにするためである。

## 4. 論理データモデル

### 4.1 全体の関連

```text
SettingMonth ───────> SettingSnapshot
                           │
                           ├── SnapshotService ─────> ServiceDefinition
                           ├── SnapshotTimeCategory > TimeCategoryDefinition
                           ├── SnapshotRate
                           ├── SnapshotPremium
                           └── SnapshotCountBonus

WorkRecord（訪問）
     ├─ work_dateからSettingMonthを選択
     └─ WorkTask [1..N] ──> ServiceDefinition
                            TimeCategoryDefinition（任意）

ClosingRuleHistory ── effective_from_year_month以降の給与期間に適用
MonthlyAllowance ────> PayrollPeriodKey
AnnualSummarySetting ─ closing_month（現在値1行）
```

### 4.2 年月とスナップショット

#### `setting_month`

| 項目 | 内容 |
| --- | --- |
| `year_month` | 対象年月。`YYYY-MM`相当の年月値オブジェクトを使用する。主キー |
| `snapshot_id` | 対象年月で使用する設定スナップショット |
| `created_at` | この年月の設定を初めて確定した日時 |
| `updated_at` | 参照先スナップショットを最後に変更した日時 |

`year_month`は端末のタイムゾーンに依存する日時ではなく、年と月だけを表す値として保持する。

#### `setting_snapshot`

| 項目 | 内容 |
| --- | --- |
| `id` | スナップショットID。主キー |
| `based_on_id` | 複製元のスナップショットID。初期スナップショットでは未設定 |
| `holiday_calendar_version_id` | 国民の祝日判定に使用するデータの版 |
| `schema_version` | スナップショット構造のバージョン |
| `created_at` | 作成日時 |

`based_on_id`は調査用の系譜であり、給与計算時には参照しない。計算に必要な設定は各スナップショット内で完結させる。

### 4.3 論理ID

サービス種類、時間区分、割増および件数加算には、表示名や設定値が変わっても変化しない論理IDを付与する。

| エンティティ | 論理IDの用途 |
| --- | --- |
| `service_definition` | 同じサービス種類を年月をまたいで識別する |
| `time_category_definition` | 同じ時間区分を年月をまたいで識別する |
| `premium_definition` | 同じ割増ルールを年月をまたいで識別する |
| `count_bonus_definition` | 同じ件数加算を年月をまたいで識別する |

表示名、標準時間、金額、適用条件および有効状態は論理ID側へ持たせず、設定スナップショット側へ保存する。

### 4.4 スナップショット内の設定

#### `snapshot_service`

| 項目 | 内容 |
| --- | --- |
| `snapshot_id` | 所属する設定スナップショット |
| `service_id` | サービス種類の論理ID |
| `display_name` | 表示名 |
| `display_order` | 表示順 |
| `is_enabled` | 対象年月で選択可能か |

主キーは`snapshot_id`と`service_id`の組み合わせとする。

`is_enabled`は新規勤務や入力補助の候補へ表示するかを制御する。スナップショット内に計算根拠が残っている既存勤務の計算を禁止する値ではない。

#### `snapshot_time_category`

| 項目 | 内容 |
| --- | --- |
| `snapshot_id` | 所属する設定スナップショット |
| `time_category_id` | 時間区分の論理ID |
| `service_id` | 所属するサービス種類の論理ID |
| `display_name` | 表示名 |
| `standard_minutes` | 標準所要時間。整数分 |
| `display_order` | 表示順 |
| `is_enabled` | 対象年月で選択可能か |

任意時間を入力するタスクでは、そのタスクの実勤務分数を使用する。時間区分を使用しない入力を許可する場合、`work_task.time_category_id`は未設定とする。

#### `snapshot_rate`

| 項目 | 内容 |
| --- | --- |
| `snapshot_id` | 所属する設定スナップショット |
| `service_id` | 対象サービス種類 |
| `time_category_id` | 対象時間区分。サービス種類単位の単価では未設定を許容 |
| `rate_type` | `Hourly`または`FixedPerRecord` |
| `amount_yen` | 整数円の単価 |

同じスナップショット内で適用対象が重複しないよう、一意制約を設ける。時間区分単位の単価をサービス種類単位の単価より優先し、任意時間入力ではサービス種類単位の単価を使用する。詳細は[給与計算仕様書](salary_calculation_specification.md)に従う。

互換性のため`FixedPerRecord`という永続値は維持するが、複数タスク対応後は単価と割増のどちらでもタスク1件当たりを意味する。

#### `snapshot_premium`

| 項目 | 内容 |
| --- | --- |
| `snapshot_id` | 所属する設定スナップショット |
| `premium_id` | 割増の論理ID |
| `display_name` | 表示名 |
| `calculation_type` | `Percentage`、`FixedPerHour`または`FixedPerRecord` |
| `percentage_basis_points` | 割合加算値。割合方式の場合のみ使用 |
| `amount_yen` | 固定額。固定額方式の場合のみ使用 |
| `start_time_minutes` | 対象時間帯の開始。0時からの整数分。未指定可 |
| `end_time_minutes` | 対象時間帯の終了。0時からの整数分。未指定可 |
| `uses_national_holidays` | 国民の祝日を条件に含めるか |
| `is_enabled` | 対象年月で使用するか |

対象曜日、個別日付および対象サービス種類は、それぞれ子テーブルで複数保持する。

- `snapshot_premium_weekday`
- `snapshot_premium_date`
- `snapshot_premium_service`

割合は浮動小数点数ではなく整数のbasis pointで保持する。例えば25%は`2500`とする。計算式と丸め位置は[給与計算仕様書](salary_calculation_specification.md)に従う。

#### `snapshot_count_bonus`

| 項目 | 内容 |
| --- | --- |
| `snapshot_id` | 所属する設定スナップショット |
| `count_bonus_id` | 件数加算の論理ID |
| `display_name` | 表示名 |
| `amount_yen` | 訪問1件当たりの整数円 |
| `is_enabled` | 対象年月で使用するか |

対象サービス種類は`snapshot_count_bonus_service`で複数保持する。対象サービスが登録されていない場合は全サービスを対象とする。対象サービスがある場合は、訪問内のいずれかのタスクが一致するとき訪問へ1回適用し、同じルールへ一致するタスク数では適用回数を増やさない。

### 4.5 締め日履歴

#### `closing_rule_history`

| 項目 | 内容 |
| --- | --- |
| `id` | 締め日履歴ID |
| `effective_from_year_month` | この締め日を適用し始める給与期間年月 |
| `closing_day` | 1から31。月末締めでは未設定 |
| `is_end_of_month` | 月末締めか |
| `created_at` | 作成日時 |

対象の給与期間年月以下で、`effective_from_year_month`が最も新しいレコードを適用する。給与期間年月は、その給与期間の終了日が属する年月とする。

給与期間の終了日は対象月の締め日、開始日は前の給与期間の終了日の翌日とする。指定日が存在しない月は月末を終了日とする。

### 4.6 月額手当

#### `monthly_allowance`

| 項目 | 内容 |
| --- | --- |
| `id` | 月額手当ID |
| `payroll_period_year_month` | 対象給与期間の年月キー |
| `display_name` | 表示名 |
| `amount_yen` | 整数円 |

月額手当は設定スナップショットへ含めず、給与期間へ直接関連付ける。同じ給与期間に複数の月額手当を登録できる構造とする。

### 4.7 勤務記録との関連

`work_record`は訪問の集約ルートとして少なくとも次の値を保持する。

| 項目 | 内容 |
| --- | --- |
| `id` | 勤務記録ID |
| `work_date` | 訪問全体で共通のローカル日付 |
| `source_basic_shift_id` | 基本シフトから作成した場合の反映元識別子 |
| `source_work_record_id` | 日単位複製で作成した場合の複製元訪問ID |
| `tasks` | 1件以上の`work_task` |

`work_task`は少なくとも次の値を保持する。

| 項目 | 内容 |
| --- | --- |
| `id` | タスクID。訪問の再編集と形式3の往復で維持する |
| `work_record_id` | 親の勤務記録ID |
| `service_id` | サービス種類の論理ID |
| `time_category_id` | 時間区分の論理ID。任意時間入力では未設定可 |
| `input_mode` | `TimeRange`または`Duration` |
| `work_minutes` | 給与計算対象となる整数分 |
| `start_time_minutes` | 必要な場合の開始時刻 |
| `end_time_minutes` | 必要な場合の終了時刻。日付をまたいでも0時からの分で保持する |
| `display_order` | 訪問内の0始まりの表示順 |
| `source_service_preset_id` | 入力補助として使用したサービス設定ID |

`開始・終了時刻`入力ではタスクごとに勤務分数を時刻差から算出する。`勤務時間`入力で時刻条件の割増が存在する場合は、タスクの開始時刻と勤務分数から終了時刻を算出して保存する。どちらの入力方式でも、保存済みの勤務分数と勤務区間は一致させる。タスク間の時刻関係は検証しない。

いずれかのタスクのサービス種類または時間区分が対象年月の設定スナップショットに存在しない場合は、別の設定へ自動変換しない。訪問全体を未計算とし、タスクID付きで不足設定を利用者へ表示する。対象項目がスナップショット内に存在して`is_enabled = false`である場合は、新規入力候補には表示しないが既存タスクの計算には使用する。

基本シフト自体は1件以上の基本シフトタスクを持つ現在値として保持し、設定スナップショットには含めない。基本シフトから確定済み訪問と全タスクを作成した後は、元の基本シフトまたはそのタスクを変更しても作成済み訪問を変更しない。

訪問の保存、編集、削除および複製は全タスクを含む集約単位で行う。タスク0件、空または重複したタスクID、および重複した表示順は不変条件違反とする。表示順は保存前に0始まりの連番へ正規化する。

Domainの`WorkRecord`は給与計算と不変条件に必要な訪問日と`WorkTask`だけを持つ集約ルートとする。Applicationの`WorkRecordDto`は同じ親子内容に加え、親へ`SourceBasicShiftId`、`SourceWorkRecordId`および保存操作ID、子へ`SourceServicePresetId`を保持する。リポジトリ契約はApplication DTOを扱い、保存前と読取後にDomain集約へ変換して不変条件を検証する。基本シフトも`BasicShiftDto`が1件以上の`BasicShiftTaskDto`を持つ同じ親子方針とし、タスクだけの公開リポジトリ操作は設けない。

### 4.8 祝日データ

国民の祝日データはアプリ更新によって変更される可能性があるため、版を識別できる構造にする。

| テーブル | 内容 |
| --- | --- |
| `holiday_calendar_version` | データ版、出典、参照日 |
| `holiday_date` | データ版、日付、祝日名 |

設定スナップショットは使用する祝日データ版を参照する。アプリ更新で祝日データを追加しても、作成済み年月の参照先を暗黙に変更しない。

## 5. 更新処理

### 5.1 新しい年月を初めて使用する場合

1. 対象年月の`setting_month`を検索する。
2. 存在しない場合は、対象年月より前で最も新しい`setting_month`を取得する。
3. 直近月の設定内容を引き継ぐ。直近スナップショットの祝日データ版が、端末内にある検証済みデータの最新版と同じ場合は、同じスナップショットを参照する`setting_month`を作成してよい。
4. 祝日データ版が古い場合は、直近スナップショットを複製して祝日データ版だけを端末内の最新版へ更新し、その新しいスナップショットを参照する。最新版は`source_reference_date`で比較し、アプリ同梱版と正しくインポートされた版のうち新しいものを使用する。これにより、確定済み年月を変えず、新しく使用する年月には利用可能な最新の祝日を適用する。
5. 直近月が存在しない場合は、初期設定から作成した初期スナップショットを参照する。

この処理は、対象年月へ勤務を初めて登録するとき、または対象年月の設定画面を初めて確定するときにトランザクション内で実行する。単にカレンダーを閲覧しただけでは作成しなくてよい。

### 5.2 選択年月の設定を変更する場合

1. 対象年月の`setting_month`を作成または取得する。
2. 現在参照している設定スナップショット全体を複製する。
3. 複製先へ利用者の変更を適用する。
4. 複製先の参照整合性と計算可能性を検証する。
5. `setting_month.snapshot_id`を複製先へ付け替える。
6. 影響する対象年月の計算キャッシュがあれば無効化する。
7. 以上を1つのデータベーストランザクションで確定する。

検証または保存に失敗した場合は、参照先を変更しない。

### 5.3 締め日を変更する場合

1. 利用者が適用開始となる給与期間年月を指定する。
2. `closing_rule_history`へ新しい履歴を追加する。
3. 適用開始月より前の履歴は変更しない。
4. 適用開始月以降の給与期間キャッシュがあれば無効化する。
5. 対象となる勤務記録の所属給与期間と集計額を再計算する。

同じ適用開始年月の履歴がすでに存在する場合は、その行を直接更新せず、置換処理をトランザクションとして扱う。変更履歴自体の監査保存は初期リリースの対象外とする。

### 5.4 前月の給与設定をコピーする場合

1. 選択年月と、その直前のカレンダー年月が参照する設定スナップショットを取得する。
2. 前月スナップショットからサービス種類、時間区分、単価、割増および件数加算を複製する。
3. 祝日データ版は前月からコピーせず、選択年月が現在参照している版と端末内最新版のうち新しい版を使用する。
4. 選択年月の計算可能性と既存勤務への影響を検証する。
5. 選択年月だけを新しいスナップショットへ付け替え、他の年月は変更しない。

以上を1つのトランザクションで実行する。前月が未作成の場合は、前月より前で最も新しい設定または初期設定から前月相当の内容を決定する。

## 6. 削除と無効化

- 勤務記録または基本シフトから参照されている論理IDは物理削除しない。
- 利用者がサービス種類、時間区分、割増または件数加算を削除した場合は、新しい設定スナップショットで`is_enabled = false`とする。
- サービス種類と時間区分の無効化は新規入力候補から外す操作であり、同じスナップショットに残る既存勤務の計算根拠を削除しない。割増と件数加算の無効化は、そのルールを対象年月の新規・既存勤務へ適用しない操作とする。
- 無効化前に作成された他の年月の設定スナップショットは変更しない。
- 対象年月に既存の勤務記録がある場合は、単価行の削除など計算不能になる変更を保存前に警告する。サービス種類または時間区分の無効化だけでは既存勤務を未計算にしない。割増または件数加算の無効化では、既存勤務の再計算後に減少する見込み額と、影響タスク数ではなく重複を除いた影響訪問数を確認表示する。
- 利用者が変更を確定した結果として計算不能になった勤務記録は、推測値を使用せず未計算として表示する。

## 7. エクスポートとインポート

### 7.1 エクスポート対象

- すべての`setting_month`
- 初期設定スナップショットのID
- `setting_month`から参照される設定スナップショットとその子データ
- 参照されるサービス種類、時間区分、割増および件数加算の論理ID
- 締め日履歴
- 月額手当
- 年間締め月の現在設定
- 基本シフトと全基本シフトタスク
- 訪問としての勤務記録と全勤務タスク
- 参照中の祝日データ版と、その版に属するすべての祝日日付
- エクスポート形式およびスキーマのバージョン

初期スナップショットではなく、どの年月からも参照されていない古いスナップショットは、給与計算の再現に不要なためエクスポート対象外としてよい。

同梱データの適用版マーカーは端末ローカル状態であり、給与計算の再現に必要なデータではないためエクスポートしない。インポート候補では未適用として初期化し、全置換コミット後にlive DBへ未適用の同梱祝日版を再投入してから画面状態をリセットする。

### 7.2 インポート時の検証

- すべての年月が存在する設定スナップショットを参照していること。
- 初期スナップショットIDがエクスポート内の設定スナップショットを参照していること。
- スナップショット内の論理ID参照が解決できること。
- 同じスナップショット内で単価や適用条件が不正に重複していないこと。
- 締め日履歴の適用開始年月が重複していないこと。
- 金額が整数円であり、分数、日付および時刻が許容範囲内であること。
- データ形式とスキーマのバージョンが対応範囲内であること。
- 形式3のすべての基本シフトと訪問が1件以上のタスクを持ち、親子参照が解決できること。
- 形式3のタスクIDが空または重複しておらず、親内の表示順が重複せず0始まりの連番へ正規化できること。
- 形式1・2の基本シフトと勤務記録が、同じ入力内容を持つタスク1件の親へ変換できること。

検証完了後に全データを1つのトランザクションで置換する。置換前データは、その後の同梱祝日版の再投入と最終検証が完了するまで復元可能に保持する。再投入を含む途中処理に失敗した場合は置換前データへ戻し、Sessionおよび画面キャッシュを破棄しない。

## 8. 整合性と実装上の制約

- 金額、勤務分数および割合の内部表現に浮動小数点数を使用しない。
- 外部キー制約を有効にする。
- スナップショットの子データは作成完了後に更新または削除しない。
- `setting_month`の参照先変更とスナップショット作成は同一トランザクションで行う。
- 給与計算は`WorkRecord（1件以上のWorkTask） + SettingSnapshot + HolidayCalendar`を入力とする副作用のない処理として、[給与計算仕様書](salary_calculation_specification.md)に従って実装する。
- 勤務記録の日付を変更した場合は、変更後の勤務年月の設定スナップショットを使用して再検証・再計算する。
- 未参照スナップショットの物理削除は必須機能としない。実施する場合は、どの年月からも参照されていないことをトランザクション内で確認する。

## 9. 自動テストで確認する事項

- 1か月の設定変更が他の年月の設定および計算結果を変えない。
- 同じスナップショットを参照する2か月の一方を変更すると、変更した月だけが新しいスナップショットを参照する。
- 月をまたぐ給与期間で、各勤務日のカレンダー年月に対応する設定が使われる。
- 日付をまたぐタスクで訪問日の年月に対応する設定が使われる。
- 締め日変更が指定した給与期間年月以降だけへ反映される。
- 対象月に存在しない締め日は月末として扱われる。
- 設定変更後も変更対象外の過去月を同じ結果で再計算できる。
- 無効化したサービス種類を参照する過去月の勤務記録を、その月の旧設定で再計算できる。
- インポート失敗時に既存の設定履歴と勤務記録が変化しない。
- エクスポート後に別のデータベースへインポートしても、年月ごとの計算結果が一致する。
- 前月の給与設定をコピーしても、選択年月以外の設定と計算結果、および選択年月の新しい祝日データ版が変化しない。
- 年間締め月を変更して年間累計を表示しても、年月別設定スナップショット、締め日履歴、勤務記録および月額手当を変更しない。
- 同じ訪問の複数タスクへ、訪問の日付の同じ設定スナップショットが適用される。
- 対象サービス付き件数加算は、同じ訪問の一致タスク数にかかわらず訪問へ1回だけ適用される。
- 訪問の保存、複製、エクスポートおよびインポートでタスクID、表示順、入力内容および親子関係が維持される。
