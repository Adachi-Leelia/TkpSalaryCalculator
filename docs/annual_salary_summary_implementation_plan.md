## 2. 背景と目的

現状のホーム画面では、選択中の1給与期間について給与見込み合計と内訳を確認できるが、同じ年次区分に属する給与期間の累計を確認できない。

本対応では、現在表示している給与期間を終点とする「年間給与見込み累計」を、既存の月次給与見込み合計と同じ画面に追加する。また、年間累計の区切りとなる年間締め月を利用者が設定できるようにする。

既存仕様の「給与締め日」と、本対応の「年間締め月」は異なる。

- 給与締め日：各給与期間の開始日と終了日を決定する。
- 年間締め月：どの給与期間年月から年間累計を開始するかを決定する。

## 3. 確定要件

### 3.1 年間累計の終点

年間累計は、ホームで選択中の給与期間までを対象とする。年間締め月が12月で、2026年8月分を表示している場合、2026年1月分から2026年8月分までを合計する。

将来の給与期間に勤務記録が存在していても、選択中の給与期間より後は年間累計へ含めない。

### 3.2 集計境界

年間累計の範囲は暦日ではなく、`PayrollPeriodKey`が表す給与期間年月で決定する。

例えば給与締め日が20日の場合も、2026年8月分を表示しているときは「2026年1月1日から8月31日」ではなく、「2026年1月分の給与期間開始日から2026年8月分の給与期間終了日」までを集計する。

給与締め日が途中で変更されている場合は、既存の締め日履歴を使用し、各給与期間の実際の開始日と終了日を算出する。

### 3.3 年間締め月

- 指定可能な値は1月から12月とする。
- 未設定時および既存データからの移行時は12月締めとする。
- 12月締めの年間区分は1月分から12月分とする。
- 3月締めの年間区分は前年4月分から当年3月分とする。
- 年間締め月は給与額の計算式や勤務記録を変更せず、年間累計のグルーピングだけを変更する。
- 年間締め月の履歴は保持せず、現在値を過去の年間累計表示にも適用する。

### 3.4 集計対象

年間給与見込み累計には、対象となる各給与期間の次の金額を含める。

- 基本給与
- 割増
- 件数加算
- 月額手当

月額手当は、登録先の給与期間について1回だけ加算する。勤務日または日別結果へ配賦しない。

計算不能な勤務記録は推測して金額へ含めない。年間範囲内の未計算勤務記録数を集計し、1件以上ある場合は年間累計の近くへ「未計算N件を除く」と表示する。

### 3.5 表示名称

アプリが表示する金額は確定給与ではなく見込み額であるため、画面上の名称は「年間給与見込み累計」とする。

## 4. 年間範囲の決定規則

選択中の給与期間キーを`selected`、年間締め月を`closingMonth`とする。

1. `selected`が属する年間区分の終了給与期間を求める。
2. 終了給与期間から11か月戻した給与期間を年間区分の開始とする。
3. 実際の累計対象は、年間区分の開始給与期間から`selected`までとする。
4. 勤務日の検索範囲は、開始給与期間の開始日から`selected`の終了日までとする。

例：

| 年間締め月 | 選択中の給与期間 | 年間区分 | 累計対象 |
| --- | --- | --- | --- |
| 12月 | 2026年8月分 | 2026年1月分～12月分 | 2026年1月分～8月分 |
| 12月 | 2026年12月分 | 2026年1月分～12月分 | 2026年1月分～12月分 |
| 12月 | 2027年1月分 | 2027年1月分～12月分 | 2027年1月分のみ |
| 3月 | 2027年1月分 | 2026年4月分～2027年3月分 | 2026年4月分～2027年1月分 |
| 3月 | 2027年3月分 | 2026年4月分～2027年3月分 | 2026年4月分～2027年3月分 |
| 3月 | 2027年4月分 | 2027年4月分～2028年3月分 | 2027年4月分のみ |

## 5. タスク分割

本対応は次の2タスクに分ける。タスク1は12月締めのデフォルトだけで単独リリース可能とし、タスク2で設定変更機能を追加する。

### タスク1：年間給与見込み累計の計算・ホーム表示

#### 5.1.1 Domain

- 1～12月だけを許可する`AnnualClosingMonth`値オブジェクトを追加する。
- `AnnualClosingMonth.Default`は12月とする。
- 選択中の`PayrollPeriodKey`と`AnnualClosingMonth`から、年間区分の開始、終了および累計終点を算出する純粋なドメインサービスを追加する。
- 年越し、12月締め、12月以外の締め月を単体テストする。

タスク1のホーム画面は`AnnualClosingMonth.Default`を使用する。タスク2の追加時に同じ値オブジェクトへ保存済み設定を渡す。

#### 5.1.2 Application

- `AnnualSalarySummaryDto`を追加する。
  - 年間区分の開始給与期間
  - 年間区分の終了給与期間
  - 累計対象の終了給与期間
  - 年間給与見込み累計
  - 年間範囲内の未計算勤務記録数
- 月次サマリーと年間サマリーを一緒に返す`HomeSalarySummaryDto`を追加する。
- `ISalaryQueryUseCase`へ、選択中の給与期間キーと年間締め月を受け取るホーム用読み取りメソッドを追加する。
- 既存の`GetPayrollPeriodAsync`は計算内訳画面などのために維持する。

ホーム用読み取りでは、月次APIを対象月数分繰り返し呼ばない。次の処理を1回の要求内で行う。

1. 締め日履歴から年間累計の実日付範囲を決定する。
2. 対象範囲の勤務記録を`StreamRangeAsync`で一括取得する。
3. 対象日付に必要な設定スナップショットと祝日データを月単位で一括取得する。
4. 対象給与期間範囲の月額手当を一括取得する。
5. 日別結果を給与期間ごとにまとめ、既存の給与期間集計規則で各期間を集計する。
6. 開始給与期間から選択中の給与期間までの金額と未計算件数を加算する。
7. 選択中の給与期間については、同じ読み取り結果から従来の月次サマリーも生成する。

月額手当のN+1取得を避けるため、`IMonthlyAllowanceRepository`へ給与期間キー範囲を指定する読み取りメソッドを追加し、SQLiteでは`payroll_period_year_month`の範囲検索を使用する。

年間合計は正本としてDBへ保存しない。性能測定で必要性が確認された場合だけ、元データから再構築可能なキャッシュを別途検討する。

#### 5.1.3 Presentation

- `HomeViewModel`がホーム用読み取りメソッドを呼び、月次と年間の表示状態を同時に更新する。
- 前の給与期間、次の給与期間、現在の給与期間への移動時に年間累計も再取得する。
- 勤務記録、給与設定、締め日履歴または月額手当の変更後は、既存のデータ変更追跡を使って年間累計も再読込する。
- 古い要求の完了結果で新しい表示を上書きしない既存の要求世代管理を維持する。

ホームの給与見込み合計カード内で、月次内訳の下または月次合計の補助領域に次を小さめに表示する。

```text
年間給与見込み累計
2026年1月分～8月分
978,000円
未計算2件を除く
```

- 月次の給与見込み合計を主表示として維持する。
- 年間累計額は月次合計より小さい文字サイズとするが、金額として判読できるサイズを確保する。
- 集計範囲を金額と同時に表示し、どの年次区分かを曖昧にしない。
- 未計算件数が0件の場合、警告文は表示しない。
- 0円でも年間累計欄は表示する。
- スクリーンリーダーには、表示範囲、金額および未計算件数を一続きの意味として提供する。

### タスク2：年間締め月の保存・設定画面

タスク2はタスク1の完了後に実施し、ホームが使用する`AnnualClosingMonth.Default`を保存済み設定へ置き換える。

#### 5.2.1 データモデル・Infrastructure

- 現在値を1行だけ保持する`annual_summary_setting`テーブルを追加する。
- 主な列は次のとおりとする。
  - `id`：常に1
  - `closing_month`：1～12、NULL不可、デフォルト12
  - `created_at_utc`
  - `updated_at_utc`
- SQLiteスキーマをバージョン5へ更新する。
- 既存DBのマイグレーションでは12月締めの行を追加し、勤務記録、給与設定、締め日履歴および月額手当を変更しない。
- 新規DBにも12月締めを投入する。
- 設定の取得・保存用リポジトリを追加する。
- 保存はトランザクション内で行い、`last_data_changed_at_utc`を更新してバックアップ対象の変更として扱う。

年間締め月は端末変更後も同じ年間表示を再現するため、エクスポート対象へ含める。エクスポート形式版を更新し、次を検証する。

- 新形式のエクスポート・インポートで設定値を維持する。
- 年間締め月を持たない旧形式を受け入れる互換方針を採る場合は12月を補う。
- 非対応の将来形式は既存データを変更せず拒否する。

#### 5.2.2 Application

- 年間締め月の取得・保存を行う専用ユースケースを追加する。
- 入力値が1～12以外の場合は保存しない。
- 保存後に`AppDataChangeKind`へ年間累計設定の変更を通知し、ホーム画面のキャッシュを無効化する。
- 年間締め月変更は既存の給与計算結果や勤務記録を変更しないため、金額差分プレビューや締め日履歴は作成しない。

#### 5.2.3 Presentation

- 設定メニューに「年間累計」を追加し、独立した`SCR-ANNUAL-01 年間累計設定`画面へ遷移させる。
- 給与締め日との混同を避けるため、既存の`SCR-PERIOD-01 給与期間設定`には同居させない。
- 入力項目は「年間締め月」のPickerとし、1月から12月を表示する。
- 選択値に応じて、年間区分の例を表示する。
  - 12月締め：1月分～12月分
  - 3月締め：前年4月分～当年3月分
- 「この設定は年間累計の区切りだけを変更し、給与額や勤務記録は変更しません」と説明する。
- `EditableViewModelBase`、未保存変更確認および`FixedSaveBar`を使用する。
- 保存成功後に設定画面へ戻り、成功メッセージを表示する。

## 7. テスト計画

### 7.1 Domain

- 年間締め月12月で、1月、途中月、12月を選択した範囲。
- 年間締め月3月で、4月、翌年1月、翌年3月を選択した範囲。
- 1月締めなど、開始月と終了月が年をまたぐ境界。
- 年間締め月に0、13などを指定した場合の拒否。

### 7.2 Application

- 複数給与期間の基本給与、割増、件数加算および月額手当が正しく合算される。
- 選択中の給与期間より後の勤務記録と月額手当を含めない。
- 月額手当を各給与期間で1回だけ含める。
- 給与締め日が月末、20日、存在しない31日、期間途中で変更された場合。
- 未計算勤務を金額から除外し、年間未計算件数へ含める。
- 勤務記録がない場合に0円を返す。
- 月次サマリーと年間サマリーが同じ読み取り結果に基づく。
- キャンセルと大きな金額の加算で、不完全な結果やオーバーフローを黙って返さない。

### 7.3 Infrastructure

- 月額手当の給与期間範囲検索。
- スキーマバージョン4から5への移行で年間締め月が12になる。
- 新規DBの年間締め月が12になる。
- 不正な年間締め月をDB制約で拒否する。
- マイグレーション失敗時に既存データを維持する。
- エクスポート／インポートで1月から12月の設定値を維持する。
- 旧形式互換を採用する場合、年間締め月がないデータへ12月を補う。

### 7.4 Presentation

- 初期表示で12月締めの年間累計が表示される。
- 前月、翌月、現在へ移動したとき、範囲と金額を一緒に更新する。
- 遅く完了した古い要求で新しい選択月を上書きしない。
- 未計算件数が1件以上のときだけ注意表示する。
- 0円、長い金額、最大文字サイズで表示が崩れない。
- 年間締め月の保存、未保存変更の破棄確認、保存失敗からの再試行。
- 設定保存後、ホームへ戻った際に新しい年間区分で再計算される。
- TalkBackで年間範囲、累計額および未計算件数を理解できる。

### 7.5 性能

- 既存の基準データ約21.9万件を使用する。
- ホームの月次・年間集計を操作開始から2秒以内に表示することをP0条件として追加する。
- SQL回数と取得範囲を計測し、勤務記録ごとまたは給与期間ごとのN+1取得がないことを確認する。
- 性能条件を満たさないことを計測で確認するまで、年間集計キャッシュは追加しない。

## 8. 受入条件

### タスク1

- デフォルト12月締めで、選択中の給与期間が2026年8月分の場合、2026年1月分から8月分までの給与見込み額が合算される。
- 給与締め日が20日でも、暦日1月1日からではなく1月分の給与期間開始日から集計される。
- ホームの月次合計を主表示として維持し、その近くに年間範囲と年間給与見込み累計を小さめに表示する。
- 未計算勤務がある場合、その金額を推測せず、年間未計算件数を表示する。
- 月の移動、勤務記録、給与設定、締め日および月額手当の変更を年間累計へ反映する。
- 年間累計を正本としてDBへ保存しない。

### タスク2

- 利用者が1月から12月の年間締め月を設定できる。
- 未設定、新規DBおよび既存DBの移行後は12月締めになる。
- 3月締めを保存した場合、2027年1月分の年間累計範囲が2026年4月分から2027年1月分になる。
- 年間締め月を変更しても勤務記録、給与設定、給与締め日および月額手当を変更しない。
- 年間締め月がエクスポート／インポートで維持される。
- 設定変更後のホームが新しい年間区分で再計算される。

## 11. 既存仕様との関係

本計画は、既存の給与期間単位の計算を置き換えず、その結果を年間区分内で累計する機能を追加する。

- [要件定義書](requirements.md)の`BR-04 月次計算`および`FR-CALC-03 期間集計`を維持する。
- [画面遷移・画面仕様書](screen_specification.md)の`SCR-HOME-01`を拡張する。
- [給与計算仕様書](salary_calculation_specification.md)の勤務記録、日別および給与期間の計算順序を再利用する。
- [設定履歴データモデル](setting_history_data_model.md)の年月別設定選択と締め日履歴を使用し、年間締め月を給与計算設定スナップショットへ混在させない。
